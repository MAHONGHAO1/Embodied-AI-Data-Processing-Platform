# QuicStudio init 采集运维与数据治理规格

> 存储与接入要求以 [2026-09-18 三桶与逻辑资产规格](2026-09-18-quicstudio-object-storage-logical-assets-design.md) 为后续修订依据：基础完整性与 Preview 是入库审核前置条件，不是建批时可跳过的可选检查；资产仅登记逻辑引用，物理交付文件在 Export 时生成。本文保留历史描述，冲突处以后续规格为准。实现进度见 [协作基线](../../DEVELOPMENT_HANDOFF.md)，规格要求不等同于已验收功能。

## 1. 范围与目标

`init` 版本是 QuicStudio 的全新产品基线，围绕“采集任务/项目管理 → 数据包接入 → 入库审核 → 建数据批 → 标注审核 → 数据资产 → 数据集”建立最小闭环。产品界面沿用产品提供的 QuicData 重设计模板，采用公有云 Beta 的工作台形态。

本版本以 `collection_project`（采集项目）作为业务命名，不兼容旧版 `task_set` 命名。未来产品稳定后，另行编写数据库迁移脚本处理旧系统数据。

本版本交付边界到数据集版本为止，训练系统对接不在本规格范围内。本版本也不实现完整私有化拆分、复杂角色体系和边缘节点；但数据包、上传会话、数据批和标注审核的边界必须为后续扩展保留清晰接口。

## 2. 领域模型

业务层级为：

```text
Workspace
└── CollectionProject
    └── CollectionTask
        └── DataPackage
            └── Episode / Artifact
```

`Episode` 是审核与有效性判定的最小单位。界面中的“视频”即一个 Episode。`init` 不引入切分（cut）实体，Episode 保持不可分；切分由 Duance 在上传前完成，平台只接收成品 Episode。

`DataBatch` 是从多个未建批数据包中创建的逻辑治理单元，不属于采集层级。一个数据批包含多个数据包；`init` 中一个数据包最多归属一个数据批：

> **2026-09-22 最新规则（待实施）**：当前按整包组织数据批，暂不开放同包多次建批，保留包→批多关联模型，不新增包 ID 单列唯一约束。每包只有一次最终入库审核；结论前可修复失败来源，结论后补采在同任务下新建关联包。分配、最终审核、建批和资产发布分阶段冻结。执行与验收以 [本次修复计划](../../CODE_SPEC_REPAIR_PLAN_2026-09-22.md) 为准。

```text
DataPackage ──(本期仅允许一次建批；模型保留多关联)──> DataBatch
DataBatch ──> GovernanceRun / AnnotationWorkItem / ReviewWorkItem
```

`UploadSession` 是 SDK 或文件导入的一次技术会话。它负责上传进度、解析、校验、重试和审计；任务创建时预生成的数据包由上传会话关联和填充，一个会话可以关联多个数据包，但不会自行创建业务数据包，也不是用户分配、标注或审核的对象。

### 2.1 采集项目

采集项目字段：

- 名称：工作空间内唯一。
- 说明：可选。
- 负责人：可选的组织成员引用。
- 状态：`enabled` 或 `archived`。

启用项目可创建任务、数据包和上传会话；归档项目保留历史查询、预览、标注和审核能力，但禁止新增任务、数据包及上传。数据包保留 `collection_project_id`，保证历史归属稳定。

### 2.2 采集任务

采集任务字段：

- 名称、说明。
- 目标采集时长（小时），必填。
- 采集模式：本期固定为 `offline`，在线分发留待后续阶段。
- 采集 SOP，可选长文本。
- 任务用途、场景标签、训练标签、项目标签、数据模态：来自统一标签字典，可多选时按字段定义保存。
- 采集设备型号：一个任务只绑定一个型号。

任务表单不含人员字段；采集人员只在数据包分配环节指定。创建人作为审计字段由服务端自动记录，不作为可编辑表单项。任务不设地区字段。

产品模板以目标时长为唯一任务目标；数据包数量、有效时长和有效率是进度与看板指标，不提供任务级数量目标输入。

任务创建时按“默认单数据包目标时长”预生成待分配数据包。任务可以覆盖默认单包时长；不足一个标准时长的尾部生成余量包。开始采集前，管理员可以修改、增加、删除未分配的数据包。已分配的数据包不得改写，未分配包仍可调整目标时长、数量和拆分方式。

### 2.3 采集设备

设备采用“型号目录 + 可选实例”两层模型：

- 型号目录：规范厂商、型号、设备类型和支持模态；选择器优先选择已有型号。
- 设备实例：可选的 SN、资产编号和备注，用于实际硬件追溯。

本期型号目录由预置数据初始化并在后台维护，前端新建设备按钮置灰；设备自助新建与配置信息下发留待后续版本。

任务分配按设备型号，不按实例。数据包接入后如果 QRDF 上报 SN，则关联设备实例。显示名称可以作为界面别名，不参与唯一匹配。服务端负责空格、大小写和重复校验。

### 2.4 数采员与分配

本期数采员使用离线清单和 SDK 完成分发与上传，身份通过稳定的 `collector_id` 归属，不要求在线 App 联动。在线 App 登录、在线分发和在线同步留待后续阶段。

服务端生成不可变 `package_id` 和离线清单；Duance 通过 SDK 上传清单与数据文件，服务端按 `package_id` 归属，不依赖文件名或目录猜测。

只有管理员可以生成并分配离线数据包；数采员不能自助领取。本期一个包分配给一个数采员，批量选择多人时分配不同的包。后端历史责任/操作采集员双字段兼容保存，新分配填同一数采员，不要求独立负责人。人效统计计在该数采员名下。

**数据包一经分配即锁定，不可改派。** 分配错误只能作废该包并在任务下新建待分配包，作废与新建都记录审计。调整包目标时长、数量、拆分与合并只允许作用于同一任务内未分配的数据包。拆合保持总目标时长，批量分配原子校验人员与状态。规划、人员分配和清单下发分开处理；未来在线下发复用已分配 package_id，接收确认不等于自助抢单，下发重试不创建新包。

## 3. 数据包接入与入库审核

数据包是采集、接入、预览和审核的最小业务对象，包含：任务归属、项目归属、目标时长、采集责任人、采集人员、设备型号/实例、模态、实际采集时长、入库有效时长、治理后有效时长、上传完成时间、QRDF 元数据引用、当前处理状态和审核状态。

### 3.1 状态机

数据包主路径：`待分配 → 已分配 → 待上传 → 上传中 → 解析中 → 已接入 → 待入库审核 → 入库审核通过 → 已建批 → 治理中 → 已发布`。

两个终止分支：解析阶段失败进入 `解析失败`，可重新上传；入库审核不通过进入 `已作废`，不参与任何后续流转。

Episode 有三种有效性状态：`有效`、`人工不合格`（入库审核标记）、`QC 淘汰`（数据批治理标记）。两种失效状态用独立来源字段区分，不互相覆盖，保证淘汰原因可追溯。

### 3.2 上传与解析

上传会话支持 SDK、分片上传和已授权来源导入。Duance 的离线数据通过 SDK 进入上传会话。上传完成只完成接入、解析和基础可用性记录，不自动启动完整性检查、自动质检、合规检查或标注。

平台按 QRDF `capture.mode` 识别 EGO、UMI、Teleop、Simulation 等采集形态，用于列表筛选与预览策略选择。含 `media/preview/manifest.json` 的 Episode 可播放预览；缺少 Preview 时展示元信息与质检摘要，不因缺 Preview 判定接入失败。LeRobot 来源数据明确不可预览，界面给出明确提示。

QRDF 元数据保存设备、时间、模态、时长、版本和 provenance 等数据事实；平台标签保存业务分类，用于筛选、统计和数据集构建，不反向修改 QRDF 顶层事实。

### 3.3 入库审核

上传解析完成后数据包进入 `待入库审核`。入库审核由**管理员**执行，不设独立工作队列，也不需要分配机制；从队列或详情抽屉进入全屏审核页，抽屉只读。

审核以数据包为单位给出通过或不通过结论。管理员在包内逐个 Episode 查看，可将个别 Episode 标记为不合格；不标记即视为包内全部 Episode 有效。整包不通过时该数据包作废，包内全部 Episode 均不进入后续流转。

**入库审核是强制环节**：没有明确审核结论的数据包不能进入建批池。数据包列表支持多选后一键通过，用于无需逐个查看的批量场景；审计记录须区分逐包审核与批量通过，并保留操作人、时间和被标记的 Episode 清单。

每包只有一次最终入库审核结论；最终提交前允许修复失败来源并重新完成准入检查，最终结论后不在原包新增数据或重新审核。需要补采时由管理员在同任务下新建待分配包，记录来源包、原因及创建人，不自动补包、不增加任务目标。原包结论和来源保留。任务分别展示目标、入库有效、未分配计划与在途预计时长；在途预计不能当作已入库有效时长。

`init` 不实现隐私处理与脱敏。QRDF 元数据带有 `privacy_sensitive` 标记时，入库审核界面高亮提示，由管理员将对应 Episode 标为不合格，作为本期的人工兜底手段。段级脱敏属于后续的数据 pipeline 能力，届时作为独立处理阶段设计接入；本期只保证标记原样透传、不丢失，不预设其实现形式。

## 4. 数据批与治理

建数据批页面只展示**入库审核通过且尚未归属数据批**的数据包，支持按项目、任务、采集人员、设备、模态和标签筛选；用户可以切换查看已建批数据。进入数据批的只有包内有效 Episode，入库审核标记为不合格的 Episode 不参与治理、标注和资产生成。`init` 中一个数据包最多归属一个数据批。后续多次处理需求暂不进入 `init`，待产品稳定后另行设计可追溯的重复处理/版本模型。

建数据批表单按以下顺序组织：

- 数据批名称，必填。
- 场景标签、任务用途、模态、训练标签：默认从选中数据包和任务带出，只能从标签字典选择，可多选，提交前可编辑。
- 选中的数据包清单。
- 治理流程：完整性检查、自动质检、合规检查，均可勾选。
- 标注流程启用开关。
- 标注员：启用标注流程时必选，支持多选。
- 审核模式：本期固定为单审，选择一名审核员；双审作为后续扩展位，双审要求所有审核员结论一致，不一致则审核失败并交管理员处理。

数据批创建后，数据包清单、治理流程和业务标签全部锁定；修改必须新建数据批，但 `init` 默认筛选会排除已建批数据包，因此新建数据批不能重复选择同一数据包。提交建批后才创建治理作业。治理阶段失败保留失败原因和已有输出，允许只重试失败阶段；重试不改变数据批定义。

自动质检结果下沉到 Episode 级：不合格的 Episode 标记为 `QC 淘汰`，不进入标注与资产。包内全部 Episode 均被淘汰时整包淘汰，不生成资产并记录原因。

合规检查在 `init` 只核对并记录 QRDF 的合规相关标记，输出检查结论，不执行任何脱敏或内容改写动作。

标注流程启用后，前端统一显示“标注”流程，审核是标注的后置状态，不作为独立建批选项。

## 5. 标注与审核

标注员按管理员分配的整个数据包开展工作，在包内完成所有有效 Episode 的标注；已被入库审核或 QC 判定失效的 Episode 不进入标注范围。工作单位是数据包，不是单个 Episode。提交后进入审核队列。

标注审核只判定标注质量，输出通过或退回两种结论，不承担数据不合格判定——数据有效性已在入库审核和 QC 环节确定。审核通过后数据包完成标注审核；审核退回必须填写原因并回到原标注员，如标注任务已由管理员转派则回到接任标注员，修改后重新提交。所有分配、转派、提交、通过和退回动作记录审计。

管理员在建数据批时统一分配标注员和审核员，标注员支持多人协作，审核本期只支持单审。双审保留数据模型扩展位：所有审核员结论一致才算完成，不一致则审核失败并交管理员处理。标注与审核队列不提供人工领取、释放操作。分配以数据包为单位，优先按预计有效时长做负载均衡：计算每名成员当前已分配时长，将下一个数据包分给累计时长最少且具备对应能力的成员；时长相同时按稳定的成员 ID 排序。管理员可以在提交建批前调整分配；提交后不得普通编辑分配关系，但允许通过管理员转派流程调整未完成任务。退回只回到指定标注员并由管理员重新分配审核员。系统记录分配快照和每次调整原因。

管理员可将未完成的标注或审核任务转派给具备对应角色的人员，转派须填写原因。转派保留已保存的标注草稿、处理进度和历史操作记录；生效后原处理人不能再保存或提交该任务，新处理人接续处理，服务端须拒绝原处理人旧页面发出的写入。转派记录原处理人、新处理人、管理员、时间和原因，不改写历史记录的操作者。已完成任务不能转派。此规则仅适用于标注/审核任务，不解除采集数据包的分配锁定，也不修改数据批清单、流程和标签。

## 6. 有效时长口径

数据包保存两个有效时长，分别服务不同消费方，不互相覆盖：

- **入库有效时长**：入库审核通过且未标记不合格的 Episode 时长之和。入库审核完成即确定，之后不再变化。
- **治理后有效时长**：在入库有效时长基础上再扣除 QC 淘汰的 Episode 时长。随治理结果确定。

采集概览看板与采集任务进度统一使用**入库有效时长**，保证历史指标稳定、不回溯。数据资产与数据集使用**治理后有效时长**，反映实际沉淀为资产的数据量；数据资产的有效时长是其所属数据批内所有未淘汰 Episode 的治理后有效时长之和。有效率指标须注明所用口径。

## 7. 前端工作台

采用产品模板的 B 布局：业务页面标题下方显示所需的工作空间和采集项目范围；顶部只保留页面标题、语言和账号操作。侧边导航按功能分组：

```text
采集管理
  ├── 采集概览
  ├── 采集任务
  ├── 数据包
  └── 采集资源
数据治理
  ├── 数据批
  └── 标注审核
数据沉淀
  ├── 数据资产
  └── 数据集
数采配置
```

入库审核不单独开页，在数据包详情抽屉内完成。详情统一使用右侧抽屉。采集任务页沿用产品表单：任务名称、数据模态、项目标签、任务用途、训练标签、场景标签、目标时长和采集 SOP；不加入采集时间窗口，不加入人员和地区字段。

设备使用“选择已有型号”的交互，本期不提供前端新建入口。工作空间由权限中心管理，采集任务在采集管理中创建；页面范围栏不提供工作空间或采集任务的新建入口。

标签由**数采配置**统一维护，至少包含场景标签、任务用途、训练标签、项目标签和数据模态五类。管理员可以新增和停用标签；已被使用的标签只能停用，不能物理删除。建任务和建数据批时只能选择已启用标签，不允许在业务表单中临时创建标签。设备软件版本不进入标签字典，从 QRDF `capture.app_version` 读取展示。

工作空间是采集与数据流转阶段的范围容器；进入数据集阶段后，数据集以自身的来源、版本和标签作为主要上下文，不再依赖当前采集项目。采集项目只在采集管理和数据接入页面生效。采集管理页面将工作空间和采集项目选择器放在模块标题下方；数据概览保留工作空间范围，并将采集项目作为单选筛选项。

后端将前端“工作空间”命名为 `CollectionWorkspace`（采集工作空间）。采集工作空间只约束采集管理、数据接入、数据批治理和数据标注/审核；从数据资产开始不再受当前采集工作空间限制。数据资产目录和数据集可以跨采集工作空间组合，保留来源采集工作空间、项目和数据批用于追溯和可选筛选。

数据包预览优先支持视频：上一个/下一个 Episode、时间轴、关键帧、包元数据、采集人员、设备、时长和治理报告 Tab。其他模态在 `init` 先展示元数据和可用性状态，后续扩展专用预览器。

## 8. 数据资产与数据集

数据资产以数据批为单位：一个数据批及其所包含数据包中的全部有效 Episode 集合构成一个数据资产，数据批与数据资产是一对一关系。数据批内被 QC 淘汰的 Episode 直接排除并记录原因，但不拆分成多个资产；系统异常允许重试。每个数据包最终都必须有明确结果，数据批内全部 Episode 被淘汰则不生成空资产，并将数据批标记为无可发布资产。完整性检查、QC、合规检查和标注审核均允许在建批时跳过，由用户自行判断；资产记录数据批级各项流程为已通过、已跳过、已淘汰或未生成。数据批内所有已启用流程全部结束后自动生成一个资产，全部跳过时建批后直接生成。

数据集按版本创建。一个数据集包含多个固定版本；每个版本保存不可变的数据资产清单，同一数据批资产在同一版本内不得重复。资产可以被多个数据集复用，修改数据集内容通过创建新版本完成。QRDF 数据集从全局已授权数据资产中选择，不受采集工作空间限制；组集时选择的是数据批资产，不重新选择包或 Episode。

数据集列表提供**格式转换**操作，可选 QRDF `0.2` 或 LeRobot `3.0`。转换产出导出件（Export），不创建新的数据集版本，版本清单保持不变。直接导入的 LeRobot 数据集不支持反向转换为 QRDF，该操作置灰。

已被导出引用的数据集版本只能归档，不能物理删除；后续接入训练后，训练引用同样纳入该保护。归档保留版本清单、来源关联及引用关系，保证历史可追溯；删除整个数据集也不得级联删除这些受保护版本。

LeRobot 数据默认视为无需治理的数据集来源，独立于采集工作空间直接导入；一期只做格式与完整性校验、原格式预览限制和数据集版本创建，不进入采集项目、数据包、数据批或标注审核流程。

## 9. API 与一致性边界

### 9.1 一期角色与操作边界

一期只设管理员、标注员、审核员三个固定角色，不提供自定义角色、逐项功能授权或逐个资产/数据集的成员授权。

- 管理员：管理用户及角色、采集工作空间、采集项目、采集任务、设备和标签；负责数据包分配、入库审核、建批、人员分配、异常处理，以及数据资产、数据集版本、LeRobot 导入和归档管理。
- 标注员：查看分配给自己的标注任务及所需数据，编辑、保存、提交标注，并处理退回任务。
- 审核员：查看分配给自己的标注审核任务及所需数据，执行通过或退回；退回必须填写原因。

入库审核是管理员职责，不下放给审核员。管理员在建批时从对应角色人员中选择标注员和审核员。服务端校验角色及任务分配关系，不仅依赖前端隐藏按钮。采集工作空间用于采集与治理的业务归属及筛选；数据资产和数据集管理不因当前采集工作空间选择而缩小范围。数采员档案是采集来源身份，不额外引入第四种工作台角色。

### 9.2 API 校验

API 按资源划分：`collection-projects`、`collection-tasks`、`data-packages`、`upload-sessions`、`data-batches`、`annotation-work-items` 和 `review-work-items`。浏览器只能使用服务端生成的资源 ID 和短期授权地址，不能指定存储桶、对象键或原始 URI。

服务端必须校验：

- 项目状态和工作空间归属。
- 任务、数据包、数据批之间的归属关系。
- 管理员的数据包分配权限，以及分配时采集责任人与采集人员均已指定。
- 数据包分配后的改派拒绝；未分配包的调整允许。
- 入库审核的管理员身份、数据包状态，以及批量通过与逐包审核的审计区分。
- 未完成入库审核的数据包不得进入建批池。
- 管理员、标注员、审核员的固定操作边界，以及标注/审核任务的分配关系。
- 数据批一次性归属和建批快照。
- 标注/审核转派的管理员身份、任务未完成状态、接任者角色，以及转派后的旧处理人写入拒绝。
- 离线清单的 `package_id`、任务和项目一致。
- 数据集及版本删除前的引用检查，禁止通过级联删除绕过版本保护。

重复上传、失效 `package_id`、跨项目数据包、身份不匹配和锁定对象修改必须返回明确业务错误，不能静默归属或覆盖历史记录。

## 10. 验证要求

后端验证覆盖：项目启用/归档规则、任务创建与时长拆包、设备型号唯一性、标签字典启停规则、管理员离线分配与改派拒绝、离线 SDK 归属、入库审核结论与 Episode 不合格标记、整包作废与不自动补包、建批筛选与锁定、建批人员分配、QC 的 Episode 级淘汰、单审流程和双审扩展规则、治理跳过与淘汰、资产自动发布、有效时长双口径计算、数据集版本与格式转换规则、审核退回和审计记录。

前端验证覆盖：分组导航、任务创建表单、设备型号选择、数据包批量分配、入库审核抽屉与批量通过、建批筛选与流程勾选、数据包预览、标注/审核队列和状态展示、数据集格式转换按钮的可用与置灰状态。

数据集生命周期验证覆盖：被引用的版本不能物理删除，归档后历史清单和引用仍可追溯，删除父数据集不能绕过引用保护。

角色验证覆盖：管理员管理、入库审核与分配操作；标注员只能操作分配给自己的标注任务；审核员只能处理分配给自己的标注审核任务；服务端拒绝不符合角色或分配关系的请求。

转派验证覆盖：未完成任务可由管理员转派、已完成任务不可转派；草稿和历史记录保留；旧处理人不可继续写入、新处理人可接续；审核退回路由到当前负责的标注员。

端到端验收路径：在权限中心创建工作空间 → 在采集管理创建启用采集项目和离线任务 → 预生成离线数据包和清单 → 管理员分配采集责任人与采集人员 → SDK 接入 → 管理员入库审核并标记不合格 Episode → 筛选入库通过且未建批数据包 → 在数采配置维护并选择标签 → 创建数据批、分配标注员和单名审核员 → 按选择的流程治理 → 标注员处理 → 单审通过或退回 → 自动发布数据资产 → 跨采集工作空间选择资产创建数据集版本 → 执行格式转换导出。

## 11. 明确不在 init 范围内

- 训练系统对接与训练任务管理。
- 在线分配、在线下发、App 拉取和在线状态回执。
- 采集 App 登录、采集人员手机号与密码重置。
- 前端新建采集设备与设备配置信息下发。
- 采集人员工作时长统计及相关看板指标。
- 平台侧切分（cut）实体。
- 隐私处理与段级脱敏；后续作为数据 pipeline 的独立处理阶段设计。
- 任务级目标数据包数量输入、采集时间窗口字段、地区字段。
- 数据包分配后的改派。
- 标注员或审核员自助领取、释放数据包。
- 创建后修改数据批清单、流程或标签。
- 同一数据包在多个数据批中重复归属，以及同一数据包的多次处理/版本管理。
- 完整私有化独立部署、细粒度商业角色体系、自定义角色及逐项功能授权。
- 非视频模态的专用可视化预览器。
- 直接导入的 LeRobot 数据反向转换为 QRDF。
