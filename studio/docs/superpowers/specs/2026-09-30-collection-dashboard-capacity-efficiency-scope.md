# 采集概览二期范围（按现有元数据裁剪）

本文件把产能看板、人效看板收敛到当前数据库已经能可靠支撑的指标。凡是需要新增元数据、依赖采集 App 上报，或当前字段只存在于不受约束的 `metadata_json` 中的指标，本期移出，不用模拟数据补齐。

## 1. 共同口径

- 过滤范围沿用数采看板：工作空间、日期、项目、任务、场景、用途、粒度、时区；不新增机器人类型、数据类型、地区筛选。
- 原始采集时长使用 `data_packages.captured_duration_s`，有效采集时长使用 `data_packages.intake_valid_duration_s`。
- 有效数据只使用已经冻结的入库审核结论；待审核仍为未知，不当作 0。
- 人员维度使用 `operator_collector_id`，设备维度使用 `collection_device_id`。缺少归属的包进入“未归属”桶，避免分组之和与总量不一致。
- 所有日/月趋势按包的 `captured_started_at` 分桶；项目、任务分布按包数，完成度按有效时长除以任务目标时长。

## 2. 本期保留指标

| 看板 | 指标 | 计算方式 | 现有字段 | 状态 |
|---|---|---|---|---|
| 产能 | 项目分布 | 各项目包数 / 筛选范围内包总数 | `data_packages.collection_project_id` | 可做 |
| 产能 | 任务分布 | 各任务包数 / 筛选范围内包总数 | `data_packages.collection_task_id` | 可做 |
| 产能 | 项目完成度 | 项目下有效时长 / 项目下任务目标时长之和 | `intake_valid_duration_s`, `target_duration_hours` | 可做 |
| 产能 | 任务完成度 | 任务有效时长 / `target_duration_hours` | 同上 | 可做 |
| 产能 | 采集时长趋势 | 按日/月汇总原始时长、有效时长 | `captured_duration_s`, `intake_valid_duration_s` | 可做 |
| 产能 | 项目/任务时长明细 | 按项目、任务汇总原始/有效时长 | 同上 | 可做 |
| 产能 | 人员时长明细 | 按人员汇总原始/有效时长 | `operator_collector_id` + 包事实 | 可做 |
| 产能 | 设备时长明细 | 按设备汇总原始/有效时长 | `collection_device_id` + 包事实 | 可做 |

| 人效 | 近 7 日人员产出 Top5/Bottom5 | 按人员汇总有效采集时长排序 | `operator_collector_id`, `intake_valid_duration_s` | 可做 |

| 人效 | 人员有效产出趋势 | 按人员和日/月汇总有效时长 | 同上 | 可做 |

## 3. 本期剔除指标

这些指标不进入接口、页面、种子数据或验收标准：

| 剔除项 | 原因 |
|---|---|
| 按采集类型（Ego、Teleop、UMI、Simulation、Lerobot）统计 | `CollectionTask.capture_mode` 当前被约束为 `offline`，包上的同名值没有统一枚举和历史可靠性，不能据此分组。 |
| 机器人类型、数据类型、地区筛选及其分组 | 当前没有正式列、字典和归属规则，不能从 `metadata_json` 猜测。 |
| 机器开机到关机的工作时长 | 没有采集 App 的开关机/工作会话事实。 |
| 活跃人数、活跃时长、平均活跃时长 | 没有人员在线、心跳、会话或活动事件。 |
| 按小时的活跃时间分布 | 同上，且包采集时间不能替代人员活跃时间。 |
| 人效比率（有效产出 / 工作时长或活跃时长） | 分母不可得，不能用包时长冒充工作时长。 |
| “累计 + 环比”工作时长指标 | 缺少工作时长事实；采集时长趋势已经保留。 |

页面仍保留三个标签，但被剔除的指标不显示“建设中”占位卡，也不返回空字段；二期页面只渲染本文件第 2 节的内容。

## 4. 接口范围

二期继续按“一个看板一个接口”：

- `GET /api/v1/collection-dashboard/capacity`
- `GET /api/v1/collection-dashboard/efficiency`

两个接口复用数采看板的筛选校验和时间分桶工具。返回值只包含保留指标，不为剔除项预留 `null` 字段。`basis=all|valid` 作用于时长明细；完成度和人效产出固定使用有效时长。

## 5. 实施顺序

1. 先补齐一期已发现的事实一致性问题：补传后旧小时字段重算、有效准入事实校验来源指纹、回填与性能测试。
2. 实现产能接口、聚合测试和前端面板；种子数据只使用项目、任务、包、人员、设备及审核事实。
3. 实现人效接口、Top/Bottom5 和人员明细；对未归属人员保留单独桶。
4. 浏览器验收三个标签页、筛选联动、空数据和多工作空间权限。

如果后续要恢复被剔除的指标，先单独补充正式字段或 App 事件模型，再开新规格，不在本期通过 `metadata_json` 兜底。
