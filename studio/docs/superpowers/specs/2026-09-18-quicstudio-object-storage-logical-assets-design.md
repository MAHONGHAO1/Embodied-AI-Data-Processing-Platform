# QuicStudio 三桶存储、接入门禁与逻辑资产设计

日期：2026-09-18。状态：设计讨论已收敛，书面规格待用户审阅；尚未实现。

> **2026-09-22 最新规则（待实施）**：当前按整包组织数据批，暂不开放同包多次建批，保留包→批多关联模型，不新增包 ID 单列唯一约束。每包只有一次最终入库审核；结论前可修复失败来源，结论后补采在同任务下新建关联包。分配、最终审核、建批和资产发布分阶段冻结。执行与验收以 [本次修复计划](../../CODE_SPEC_REPAIR_PLAN_2026-09-22.md) 为准。

## 1. 目标与适用范围

建立 QuicStudio 的唯一新业务链路：客户端直传对象存储，完成接入完整性检查和预览准备后进入入库审核；数据批治理完成后只登记逻辑资产；数据集版本只保存不可变引用，在 Export 时生成物理交付文件。

本规格是 `2026-09-14-collection-studio-init-design.md` 的增量修订。获批后，存储模式、接入门禁、逻辑资产及 Export 的冲突条款以本规格为准；原规格的采集层级、强制管理员入库审核、单审、多标注员、三角色、标签字典及跨工作空间组集规则继续有效。

本轮只建设 QuicStudio，不编写旧数据迁移脚本，不操作旧 Bucket，不自动删除任何历史对象或数据库。旧业务链路不作为新系统的兼容运行路径。历史数据迁移另行设计和批准。

## 2. 已确定的决策与方案取舍

- 正式对象只存于 `raw`、`process`、`export` 三个逻辑 Bucket。
- 不保留 `official`，不新增 `asset/published` Bucket，不以 QRDF 或 LeRobot 格式划分 Bucket。
- 删除后端 `local/hybrid` 存储模式、本地权威副本、磁盘镜像以及缺少凭据时的自动降级。
- 本地开发使用 MinIO；前端 `?demo=1` 仍是独立的纯前端演示，不要求后端或 MinIO。
- 大小文件统一直传对象存储。删除 API 接收二进制分片、磁盘合并和转存的上传通路。
- 入库审核之前必须完成基础完整性检查及适用的 Preview 准备；不能通过建批时的跳过开关绕过。
- 数据批与逻辑资产至多一对一，不为资产或数据集版本复制物理数据。
- Export 异步生成真实产物，失败可重试且保留失败记录。
- `storage_root` 更名为 `scratch_root`，仅供 worker 有界、任务隔离的临时工作空间。

已经比较并排除：保留 `official` 的四桶方案（重复保存数据）；API 分片转存方案（占用 API 磁盘和带宽）；只用进程内 fake 代替本地对象服务（无法验证实际直传）。选定三桶、双 provider 适配和 MinIO 集成测试。

## 3. 存储职责与命名

| 逻辑角色 | 正式内容 | 不承担的职责 |
| --- | --- | --- |
| raw | 原始 MCAP、QRDF 源元数据及文件清单 | 预览缓存、资产发布副本、导出成品、原生 LeRobot 直传来源 |
| process | Preview、精确时间映射、缩略图、版本化标注产物、完整性/QC 报告及派生结果 | 替代 raw、充当临时目录 |
| export | 从固定数据集版本生成的 QRDF、LeRobot 目录或下载包，以及原生 LeRobot 直传来源 | 采集链路 raw 来源存储、为逻辑资产登记额外复制文件 |

Bucket 命名规则固定为 `quicstudio-{env}-{role}`，环境取 `dev`、`test`、`uat`、`prod`，角色仅 `raw`、`process`、`export`。例如：

```text
quicstudio-prod-raw
quicstudio-prod-process
quicstudio-prod-export
```

开发和测试 MinIO 使用各自环境名，不使用生产 Bucket 或凭据。云 Bucket 名称可因全局名称占用在部署时显式覆盖，但不得静默回退为旧名或创建第四种角色。

数据库保存服务器管理的对象引用：逻辑 Bucket 角色、对象键、对象版本/不可变身份、大小、校验和。对象身份不得仅依赖可覆盖的路径或短期 URL。浏览器业务请求只传资源 ID，不得指定任意 Bucket、对象键或来源 URI；浏览器授权接口可返回短期签名地址及所需请求头，其内容不记录到日志或持久化。Data 与 Train 的服务间 Export 交接是例外：Export 成功后可返回稳定的 `oss://<bucket>/<key>` 对象 URI，Train 使用自己配置的只读 OSS client 直接读取，不走 Data 代理下载，也不使用浏览器签名 URL。

资产登记、版本创建和归档均不触发复制。源文件、标注和报告一旦被资产快照引用即受保留保护；`process` 不等于可随意清理的 scratch。可重建预览可按精确引用策略重建，不能通过整桶 TTL 删除仍被引用的来源或标注。

## 4. 对象存储适配与 MinIO

业务层只调用统一对象存储接口：初始化 multipart、签名分片、分页查询分片、完成/取消上传、HEAD、按对象身份 GET/Range GET、worker 写对象和精确对象删除。仅确有调用者的功能才加入接口，不为旧链路保留空壳。

生产使用阿里云 OSS 适配器；开发/集成测试使用 MinIO S3 适配器。MinIO 是 S3 兼容服务，不是阿里云 OSS 协议模拟器；不能仅修改 endpoint 就把当前 `oss2` 客户端接到 MinIO。两者对业务暴露相同语义，各自处理签名、分页、校验和与错误映射。

- 新配置以 provider（`aliyun_oss` / `minio`）选择实现，不再选择 local/cloud/hybrid。
- 保留三项角色配置 `OSS_BUCKET_RAW`、`OSS_BUCKET_PROCESS`、`OSS_BUCKET_EXPORT`；删除 `OSS_BUCKET_OFFICIAL`，不提供旧别名。
- 本轮统一对象访问配置；删除 `STORAGE_MODE`、`OSS_KEEP_LOCAL_CACHE`、本地镜像开关及旧 `STORAGE_ROOT` 回退。被删除配置若显式设置，启动给出明确配置错误，不静默忽略。
- API/worker 内网 endpoint 与浏览器可达的签名 endpoint 分开配置，签名后不得替换 hostname。
- 凭据不可用时拒绝需要存储的操作并报告服务未就绪，不落盘兜底。生产不能因缺少 OSS 自动切到 MinIO。
- MinIO 数据存放独立的容器持久卷；它不是 API/worker 的 scratch，也不能随着临时目录清理被删除。
- 开发启动提供 MinIO 健康检查及幂等初始化三个开发桶；测试使用独立桶/前缀和凭据，清理仅限该测试创建的资源。
- CORS 只允许明确的前端 Origin 和所需方法/请求头；所有桶私有，浏览器不获得长期凭据和全桶读写权限。
- MinIO 镜像在实现时固定版本/摘要，不使用浮动 latest；接入已有本地启动命令，不改变纯前端启动入口。

MinIO 通过不代表阿里云签名、CRC、权限和 CORS 均已验收；两个适配器需要独立契约测试，云端另做受控 smoke。

协议依据：[MinIO S3 compatibility](https://min.io/product/s3-compatibility)、[阿里云 OSS 的 S3 兼容范围与差异](https://www.alibabacloud.com/help/en/oss/developer-reference/compatibility-with-amazon-s3)。

## 5. 客户端直传与接入校验

### 5.1 上传会话

1. 管理员/SDK 声明已有数据包和源文件清单。后端校验权限、包状态、文件数量/大小上限、相对路径及归属，为每个文件生成稳定的来源 ID。
2. 每个文件独立创建 multipart；所有文件类型和大小均走直传，API 不接收 MCAP、视频等文件字节。小型受限元数据声明仍可使用 JSON。
3. API 按上传会话、来源、part number 签发短期上传地址；SDK/浏览器直接上传至 raw，支持续传和授权续期。
4. 完成请求只触发后端核对。后端使用 provider 实际分片列表校验编号、数量、大小和 ETag，完成精确 Upload ID，再 HEAD 验证已完成对象。
5. 记录每个已完成对象的不可变身份并锁定清单；客户端不能通过声明完成来代替实际对象核验。全部文件完成后调度接入检查。

一个会话可包含多个包/文件；不能延续当前“OSS 仅支持单来源”的限制。业务会话与 provider upload id 分离，后者仅在服务器保存；重复完成、网络重试和 worker 重复投递必须幂等。

取消只中止所属 multipart；清理仅限精确记录、未被业务引用的未接纳对象。过期孤儿分片由 provider 生命周期兜底，不对已接纳 raw 设置盲目过期规则。

### 5.2 完整性与校验和

接入门禁不可跳过，检查：清单内文件齐备、实际大小、内容校验、QRDF 元数据结构与必需引用、MCAP 可读取性、Episode 身份/范围和必需流的结构一致性。

ETag 不作为内容 SHA-256；multipart ETag 也不作为整文件 MD5。客户端提供 SHA-256 不能被当成服务端已验证值。接入 worker 流式读取固定对象身份计算 SHA-256 并对账；provider CRC/checksum 作为适配器支持时的补充校验，不强求 MinIO 提供阿里云相同 CRC 头。

基础检查只回答“是否完整、可解析、可审阅”。动作质量、任务匹配、业务可用率等仍属建批后的 QC；基础检查不替代 QC。

### 5.3 Preview 门禁与状态

```text
逐 Episode：上传完成 → parsing → integrity_checking → pending_intake_review
                  ↘ parse_failed       ↘ integrity_failed
```

失败隔离在受影响的 Episode，包级展示各状态数量，不以任一失败阻断整包；完整规则见 `2026-09-18-quicstudio-data-backend-completion-design.md` 第 4 节。

`integrity_checking` 包括逐 Episode 预览准备，拆分记录基础检查状态和 preview 状态，不能只保存一个包级布尔值。

- 视频可预览 Episode：Preview、精确时间映射和对应 process 对象可读取并校验后才记为 `ready`。
- 无有效 Preview 时，从 raw 生成；SDK 已带 Preview 也必须验证，不能只检查 manifest 文件存在。
- Preview 排队/生成中仅该 Episode 继续等待；失败进入 `integrity_failed` 并保留原因，仅该项不能审核通过或进入建批池，不阻塞正常项。
- 原规格中的非视频模态保留 `not_applicable`：由后端根据已验证格式/模态判定，提供明确原因及元数据视图。它不是用户的跳过开关，视频缺失或生成失败不得冒充不适用。
- LeRobot 走独立数据集来源链路，不进入这条包审核门禁。
- 同包每个 Episode 独立完成基础校验且适用 Preview 为 `ready` 后，即可进入待入库审核；不等待同包其他项。失败项留在原包展示原因，无需先修复。全部失败时显示“无可审核数据”，不生成空批/资产，也不阻塞其他包。

失败保留结构化原因、检查版本、attempt 和历史记录。最终入库审核前，重试系统故障读取同一来源身份，修复缺失/损坏来源创建新上传 attempt；旧 attempt 晚到结果不得推进新 attempt。每包只有一次最终结论，通过与排除项及来源版本冻结后不再补传再审；需要补采时另建同任务下的关联包。既有批/资产/版本保持不变。

入库审核入口、批量通过与建批 API 均逐 Episode 强制检查门禁，不能只依赖前端。按包操作返回实际纳入和排除清单及原因；失败项不导致正常项整包回滚，也不得计为成功。入库有效时长按最终人工结论冻结。当前建批只选择未关联数据批的包，在事务中锁包并检查占用；保留包→批多关联模型，不新增包 ID 单列唯一约束。批内有效成员和来源版本固定，未来多次建批不能改写历史快照。

### 5.4 建批完整性检查的边界

建批表单中保留可选的“批次一致性检查”（内部可继续使用 `integrity` stage）：验证包/有效 Episode 清单、冻结来源引用、必需数据结构的兼容性及重复身份冲突，不再承担第一次检查文件完整或生成 Preview 的职责。

跳过仅跳过该批次检查，不撤销或绕过接入门禁。QC、合规及标注开关按原规格保留，标签和模态混合是否允许以实际格式/导出能力为准，不因跨工作空间自动判为冲突。

## 6. 逻辑资产与不可变数据集版本

一个数据批完成所有启用流程后，在数据库登记至多一个 DataAsset；全淘汰不产生空资产。`published` 指逻辑快照已登记，不表示写入了正式资产文件。

资产快照至少冻结：数据批 ID、纳入的有效 Episode 清单、来源对象的固定版本/身份、采用的标注修订、治理结论/报告版本、有效时长及来源工作空间/项目/任务。不能只保存 Episode ID 后在每次 Export 读取其可变的“最新标注”。

登记资产仅写业务数据库和审计，不调用对象上传、复制、转码或打包。允许读取已有对象元信息校验引用，但不得物化一份“已发布 QRDF”。

数据集版本保存固定资产清单和排序，不复制文件，不受当前采集工作空间过滤。后续 Export 必须使用该版本冻结的来源及标注，修改组集内容通过新建版本实现。

逻辑资产/版本引用保护必须覆盖底层 raw 和必需 process 对象；归档不解除引用。被淘汰 Episode 不进入 Export。Preview 不是默认训练输入，Export 不应无条件依赖可重建的 Preview，只验证当前格式必需的源文件/标注/派生结果。

## 7. 真实 Export 与 LeRobot

### 7.1 Export 状态及交付

Export 请求创建持久任务并返回 `queued`，不能立即写 `succeeded`。状态为 `queued → running → succeeded/failed`。

worker 读取固定版本清单和引用对象，生成选定的 QRDF 0.2 或 LeRobot 3.0 产物，上传至 `export` 的任务/attempt 独立前缀。只有产物清单、文件数量、大小、校验和以及必要格式校验通过，才发布完成标记。最小服务间交付返回 `oss_uri`（稳定的 `oss://` 对象定位）、格式、大小、校验和和清单摘要；不返回 AK/SK，不要求 Data 提供下载代理或短期签名 URL。URI 只有配合 Train 自己的只读 OSS client 才可读取。

数据库记录和“清单摘要的哈希”不能替代实际输出文件及文件校验。输出成功前不暴露可交付状态；DB 完成提交失败后可根据同一任务的输出清单幂等恢复。

重试显式创建新的 attempt，保留失败 attempt 的错误、时间、输入版本和输出清单；不得覆盖失败历史或修改数据集版本。网络重复请求以幂等键复用同一任务，而不是创建多个导出。

任务失败只清理其精确的未完成输出，不删除 raw、被引用 process 或其他成功导出。已成功交付的输出不在本轮新增自动过期策略；已存在 Export 引用的版本继续只允许归档。

### 7.2 原生 LeRobot

**2026-09-22 用户确认修订**：LeRobot 作为独立来源，直接上传至 export，经格式与完整性校验后创建目录数据集版本；无需先写 raw，也无需建采集包、治理或标注。版本登记引用已校验的 export 来源对象，不再为了“平台正式副本”复制文件。此前要求原生 LeRobot 来源存于 raw 的条款废止。

直传来源与后续 Export 产物使用独立前缀和不可变对象身份。被数据集版本引用的 export 直传来源受保留保护，归档不解除引用，不能作为临时输出清理；export 桶不能统一按短期导出缓存处理。

Export 原生 LeRobot 时保持原生格式生成交付目录/包，不提供反向 QRDF 转换。原生输入也须固定对象身份和清单，不能仅引用可能被外部覆盖的目录。跨来源 OSS 扫描和旧 external scope 导入不是本轮入口；不借此扩展旧数据迁移。

## 8. Worker 临时空间

`SCRATCH_ROOT` 为 worker 提供任务和 attempt 隔离的临时目录，用于解码器要求的随机访问文件、转码和导出临时文件。优先流式读取，但不要求所有媒体/格式工具在本轮改成无磁盘实现。

- API 不使用 scratch 暂存上传分片；正式数据不能只存在 scratch。
- 设置任务磁盘预算、磁盘空间检查及并发上限，超限明确失败，不无限下载完整桶。
- 仅在对象已持久化并确认状态后清理对应产物；运行中的 scratch 不能被 TTL 清理误删。
- 成功/失败均执行受控清理；进程异常遗留目录由任务租约和有界保留策略回收。
- 删除 scratch 后可从固定对象引用恢复任务；不能宣称任意时刻删除目录不影响正在运行的任务。
- MinIO 持久卷、数据库、凭据、用户目录不属于 scratch 清理目标。

| 配置、Compose、启动脚本、前端 API | 四桶及旧 local/旧上传假设 | 三桶、新命名、MinIO、直传协议和门禁 UI |

清理方法：列明路由、任务注册、调用者与测试依赖，先将保留能力接到新链路，再删除不可达/被替代实现。不能按 `qrdf`、`local`、`publish` 字符串批量删除；QRDF 解析/预览/导出库仍是有效能力，浏览器本地演示也继续保留。

旧 task-set/batch 发布入口及其前端调用不继续暴露；共享的权限、用户管理、格式编码器和媒体工具保留。替换旧语义测试为新契约测试，不以删除失败用例冒充验收。历史迁移和审计事实不篡改；用新迁移描述新表/状态与约束，生产旧数据升级另行安排。

## 10. 验收标准

1. 新环境只使用三个 QuicStudio Bucket；无 official 读写、无 local/hybrid、无缺凭据磁盘降级。
2. 客户端通过签名地址将多个 MCAP 分别 multipart 写入 MinIO，API 不接收文件字节、不产生上传分片目录；覆盖续传、过期授权、错分片、越权、取消、幂等完成和完成响应丢失。
3. 声明与真实对象大小/hash 不符、文件缺失、不可读 MCAP、视频 Preview 失败仅排除受影响 Episode，原因留在原包；同包正常项继续审核/建批。验证 8 成功/2 失败时整包只占用一次、全部失败、仍有处理中项、批量排除明细、最终审核前修复、单次最终审核及新包补采、当前已建批包不可另建新批；迟到结果不改变已冻结快照，补传或重试保留失败历史，旧 worker 结果不可污染新 attempt。
4. Preview 逐 Episode 可播放且时间映射有效；非视频不适用状态可解释，不能用于跳过视频失败。
5. 批次跳过治理不会跳过接入门禁；入库有效时长与治理后有效时长仍独立。
6. 一批至多一资产、零有效 Episode 零资产；登记资产和数据集版本前后无新增物理数据副本，以对象写入 spy/计数及数据库快照共同验证。
7. 修改后续草稿不改变已发布资产的标注修订；跨工作空间创建的同一版本两次导出使用同一固定输入。
8. Export 生成真实可读取并通过格式校验的 QRDF/LeRobot 文件；任务输出缺失时不能成功；重试有独立 attempt 且保留旧失败记录。
9. 原生 LeRobot 直接上传至 export，校验通过后版本引用固定来源，版本登记不另行复制文件；直传来源与后续 Export 产物分别管理并保护引用；反向 QRDF 请求拒绝。
10. 删除已结束任务的 scratch 不影响资产、版本和后续导出；磁盘不足明确失败；所有清理保护引用对象及 MinIO 持久卷。
11. 前端演示无需 MinIO；真实业务模式不以 mock 数据或假成功隐藏 provider 错误。
12. 运行后端与前端全量回归、新迁移空库验证、MinIO 实际直传到审核/资产/导出的端到端测试；报告区分 mock、MinIO 和真实阿里云验证，未运行的验证不得记为通过。
