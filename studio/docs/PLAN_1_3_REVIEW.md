## 修复清单

1. 修复 `scripts/start.sh`、`reset-data.sh`、`repair_v2_capture_markers.py` 遗留的 `app.*` 导入。
2. 新增 `make dev-frontend`，默认 `127.0.0.1:8090`，无需后端依赖；保留原 Make 默认目标。
3. 任务自动预生成最多 10,000 个数据包，防止极大时长/极小单包时长导致内存耗尽。
4. 未分配包的修改/删除先加行锁；作废使用带状态条件的 UPDATE，不能覆盖并发进入上传的状态。
5. 保留“不接收 ZIP”的上传约定；声明返回服务端来源 ID，SDK 对每个 MCAP 独立分片上传。
   合并时验证文件大小与 SHA-256；缺文件、超限、重复来源/路径、未知来源均拒绝。
6. 上传完成后禁止重复初始化、改写分片。未初始化 OSS 操作返回明确错误，避免 KeyError/500。
7. 取消待解析会话恢复包的原状态并清除完成时间，允许重传；不复活作废包，不取消正在解析的会话。
8. 旧 DWD 统计只处理旧 TaskSet/Batch Episode；新采集包走采集概览，避免空旧归属导致统计任务失败。
9. 测试用工作空间名使用 UUID；解析测试只断言当前工作空间的作业，避免跨测试数据污染。
10. 测试 broker/result Redis 跟随 `TEST_REDIS_URL` 的实例，不再固定连接开发环境 6379。
11. 更新两项“工作空间必须在全局顶栏”的旧前端测试，符合页面范围栏的新需求。

## 明确保留的限制

- 前端仍主要是演示数据；新增采集 API 尚未整体接入 UI。Plan 4 未实现，不以页面存在判断闭环完成。
- SDK 是离线清单 + 新 HTTP 上传协议；真实 Duance SDK 客户端适配和网络异常联调尚未验收。
- OSS 直传本轮仅支持单来源；多个 MCAP 使用 SDK 逐文件分片。没有 OSS 扫描入口。
  `authorized_import` 保留模型枚举但 API 拒绝创建未实现的模式。
- OSS provider 使用测试桩；真实云资源、Celery 多进程 worker、预览附件上传与播放未做端到端验收。
- 原始来源仍由上传会话保存声明与文件；Plan 4 接入治理/资产时需确定永久 Artifact 和预览物化方案。
- 不在已包含采集 Episode 的业务库直接 downgrade 到旧非空 TaskSet/Batch schema。
  空库升降级验证不代表业务数据可无损降级。
