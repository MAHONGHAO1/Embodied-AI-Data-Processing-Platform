# 工作空间可见范围与成员管理

2026-09-23 产品确认：数采、标注、标注审核只显示本人加入的工作空间；管理员在权限中心配置成员。这里的“自己的”指成员关系，不是创建人。训练继续按训练项目权限控制。

- `/workspace/options` 默认仅返回当前用户加入的空间，包括管理员。
- 权限中心使用管理员专属的 `scope=management` 列出全部空间；未加入空间的管理员仍可授权、撤销成员。
- 标注、审核列表及工作台、保存、提交、转派接口均校验空间成员关系；管理员不再绕过这项校验。
- 权限中心使用独立的空间选择与成员列表，避免影响业务空间和建批分配候选。授权、撤销后重新读取本人业务空间。
- 不改训练项目鉴权，不自动给任何现有账号增加成员关系。数据资产等其他服务的通用管理员权限未在此次变更中调整。

验证：362 项前端测试、30 项后端测试通过。覆盖管理员未加入时拒绝访问、授权后可见、撤销后立即拒绝、非管理员不能请求全空间管理列表，以及权限中心和建批成员状态隔离。

## 2026-09-30 变更：标注与审核不再受工作空间限制

产品确认：标注和标注审核不按工作空间成员关系限制，以分配关系为准。本节取代上文中关于标注、审核的约定；数采业务范围（`/workspace/options`、采集、入库审核）仍只显示本人加入的空间。

- 标注、审核列表的 `workspace_id` 改为可选筛选：不传时，管理员看到全部空间的工作项，其他用户看到分配给自己的全部工作项；响应带 `workspace_name` 和可筛选的 `workspaces`。
- 工作台、保存、提交、审核、转派不再校验成员关系：仍要求本人是当前分配对象（转派仅管理员），`workspace_id` 只用于定位工作项，传错返回 404。
- 建批选择标注员/审核员、转派目标只校验启用状态和角色，不再要求是该空间成员。
- 前端「数据标注」默认「全部工作空间」，可按工作项所在空间筛选；打开工作台、转派都使用工作项自己的空间，不改动当前数采空间。
