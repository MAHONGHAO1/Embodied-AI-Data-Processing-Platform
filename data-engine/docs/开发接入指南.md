# Quic Op 开发接入与代码规范指南

欢迎参与 `quic_op` 的研发工作。为保证企业级架构的长期可维护性，请在提交代码前遵守以下规范。

## 一、命名与注释规范（强制执行）

本项目遵循 Python 常规的 PEP8 命名规范：

1. **变量名与函数/方法名：下划线命名 (`snake_case`)**
   - ✅ 正确：`video_path`, `extract_frames()`, `is_initialized`
   - ❌ 错误：`videoPath`, `extractFrames()`
2. **类名与接口名：大驼峰 (`PascalCase`)**
   - ✅ 正确：`HandReconstructor`, `VideoEditor`, `QuicOperatorException`
3. **常量：全大写下划线分隔 (`UPPER_SNAKE_CASE`)**
   - ✅ 正确：`DEFAULT_SPLIT_DURATION_SEC`, `DEFAULT_RETRY_COUNT`
4. **注释要求：全中文规范注释**
   - 模块头部、类声明、核心函数定义统一使用中文 Docstring。
   - 复杂的业务逻辑分支前应补充简洁中文说明。

## 二、架构级开发禁令 (Anti-Patterns)

1. **严禁全局导入重型依赖**
   - ❌ 绝对禁止在文件顶部直接写 `import torch`、`import tensorflow`。
   - ✅ 正确做法：将模型相关逻辑放入对应领域的 `models/` 子目录，在推理函数内部通过 `def _lazy_load(self):` 做懒加载。
2. **严禁跨库私有依赖**
   - ❌ `perception` 严禁直接调用 `clean` 的私有工具函数。
   - ✅ 发现共用结构时，应上浮到 `core/data_types.py` 或 `core/exceptions.py`。
3. **严禁硬编码环境凭证**
   - ❌ `ODPS_ID = "xxx"`、`WEIGHTS_DIR = "/mnt/oss/weights"`
   - ✅ 统一使用 `core.config_manager.global_config` 读取环境变量。
4. **严禁在算子层耦合平台 I/O**
   - ❌ 不要在 SDK 算子里直接写 OSS、ODPS、S3 的访问逻辑。
   - ✅ SDK 只接收本地绝对路径或内存对象，平台调度由上层脚本负责。

## 三、新算子开发流程示例

假设要在 `perception` 库中新增一个基于 `HaMeR` 的手部重建算子：

1. **第一步：建立防腐层 (`models/`)**
   - 在 `quic_op/perception/models/` 创建 `hamer_wrapper.py`。
   - 实现 `predict_mesh()` 方法，并在方法内部完成 `torch` 懒加载和 `.pth` 权重读取。
2. **第二步：编写业务门面 (`facade`)**
   - 在 `quic_op/perception/` 中新增业务文件。
   - 调用防腐层拿到 Tensor 后，将结果转换为 `core.data_types` 契约对象再返回。
3. **第三步：过程数据持久化**
   - 统一通过 `core.persistence.JsonResultPersister` 落盘，禁止在业务类内手写零散 `json.dump`。
   - 对外返回值应同时携带结构化实体与 JSON 绝对路径（参考 `HandPoseOperatorResult` / `LowLightOperatorResult` / `HandPoseOperatorResult`）。
   - 在对应领域目录中新增业务文件。
   - 调用底层能力后，将结果转换为 `core.data_types` 契约对象再返回。
4. **第四步：SDK 能力声明**
   - 在领域包内增加 `capabilities.py`，使用 `CapabilitySpec` + `register_capability` 声明。
   - 保证可通过 `quic_op.invoke("domain.operator_id", ...)` 统一调度。
5. **第五步：单元测试**
   - 在 `tests/` 目录中编写不依赖 GPU 的 Mock 测试。
   - 确保返回结构满足 `core` 层契约，并覆盖 `list_capabilities` / `invoke`。
## 四、建议的提交流程

1. 先修改实现代码，再同步更新 `__init__.py` 导出接口。
2. 若公开 API 发生变化，必须同步更新：
   - `README.md`
   - `docs/API接口文档.md`
   - `examples/` 下的使用示例
3. 提交前至少执行一次全局搜索，确认旧命名未残留。
