# v0.8.0 · 八分钟作品集演示路线

面向具身智能、机器人数据工程和数据平台岗位，展示固定公开样例如何进入本地工作台，并经过检查、转换与独立验包。讲解时区分个人实现、上游公开数据和官方 LeRobot 库的责任边界。

## 演示前准备

- 安装 Windows、Python 3.12、Node.js 24 LTS 和 uv；首次启动与依赖安装见 README 的[安装与启动](../README.md#安装与启动)。
- 准备已通过验收的 ALOHA Coffee Episode 0–4 批次。全新环境可参考 [v0.6.0 状态文档](STATUS_v0.6.0.md) 的锁定复现命令；下载和完整转换需要较长时间。
- 为查看验收批次，在仓库根目录设置业务记录路径后启动本地服务：

  ```powershell
  $env:ROBODATA_BUSINESS_ROOT = "work/aloha-integration-r4/business"
  $env:ROBODATA_RUNS_ROOT = "work/aloha-integration-r4/runs"
  uv run --locked python -m robodata.web
  ```

- 访问 `http://127.0.0.1:8765`。演示时不要改动已验收批次；筛选或标注会使后续审核与产物失效。
- v0.8.0 起**导航在左侧栏**，顶栏只保留品牌、面包屑、仅本机状态与「收起检视」开关；右侧检视面板放当前帧、逐路检查、质检与来源锁定。数据浏览页底部有全局时间轴：播放、逐帧、拖动与 5 个百分比书签统一控制真实视频与曲线游标；快捷键为空格播放、← → 逐帧、1–4 放大对应相机、Esc 退出放大。
- 公开展示使用通过核验的[真实 ALOHA 四路相机截图](assets/workbench-v0.6.0-aloha.png)与 [v0.8.0 新界面截图](assets/workbench-v0.8.0.png)。四相机的 16:9 布局验证图使用真实交付帧但批次元数据为构造数据，已在 README 与展示页单独标注，讲解时不要把它当作业务状态证据。现有录屏包含加载和黑色视频画面，因此不作为演示素材。

## 演示流程

| 时间 | 界面与操作 | 说明重点 |
| --- | --- | --- |
| 0:00–0:45 | 介绍工作台和本地运行边界。 | Python 负责数据与业务流程；React 提供浏览、诊断和证据界面；服务仅监听本机。 |
| 0:45–2:00 | 批次总览，打开固定 ALOHA Coffee 批次。 | 查看固定 revision、来源许可、5 个 episode 和 5,500 帧；原始数据只读。 |
| 2:00–3:30 | 打开 Episode 0，逐路查看四个相机画面、帧率、分辨率和检查状态；用底部时间轴播放／逐帧，点一个百分比书签后看视频时间与曲线游标一起跳。 | 每路相机单独检查文件、解码、帧数与记录时间映射；时间映射不代表硬件同步。时间轴驱动的是本机真实视频，不是静态示意帧。 |
| 3:30–4:30 | 查看筛选、标注与审核记录。 | 本次自动验收使用明确标记的模拟审核门禁；它不代表人工判断或机器人任务成功。 |
| 4:30–6:00 | 打开运行诊断，查看最终处理运行和阶段事件。 | 解释导入、质检、转换、官方加载、输出检查和登记之间的依赖；失败运行不会成为可交付产物。 |
| 6:00–7:15 | 打开交付核验，查看官方加载、质量报告、ZIP 与独立验包状态。 | 交付凭据能回到当前批次和运行；LeRobot 格式写入及加载使用官方库。 |
| 7:15–8:00 | 总结实现范围和限制。 | 本次证明固定公开样例的数据浏览、检查和格式交付，不证明训练效果、机器人成功率或硬件同步。 |

## 可直接使用的开场

“这个作品集把公开机器人数据集接入一条可追溯的本地工作流。我实现固定来源适配、多相机逐路检查、episode 筛选与审核记录、质量验证和交付验包；官方 LeRobot 库负责格式读写。今天展示的是 ALOHA Coffee 固定 revision 的 Episode 0–4，共 5,500 帧。自动化验收为了验证业务门禁模拟了标注审核，所以它不是人工审核、机器人执行或模型效果的证明。”

## 面试追问的证据入口

| 追问 | 打开位置 |
| --- | --- |
| 数据来自哪里？ | 批次总览的固定 revision、许可和来源信息；详细校验见 [验收记录](VALIDATION_v0.6.0.md)。 |
| 多相机如何检查？ | Episode 浏览器的逐路检查状态，以及验收记录中的视频、帧数与时间映射结果。 |
| 16:9 界面重设计了什么？ | 两仓 v0.8.0 / v0.3.0 发布说明；固定 Shell、局部滚动、共用时间轴与全宽表格，均为布局层改动，不改变 API 与数据口径。 |
| 转换是否用了官方格式？ | 交付核验的官方 LeRobot 离线加载记录及数据字典。 |
| 失败时会怎样？ | 运行诊断、失败测试和验收记录中的登记门禁说明。 |
| 这证明机器人或模型有效吗？ | 不证明；本项目验收范围是数据读取、检查、转换和交付。 |

旧版 Streamlit 页面可通过根目录 `启动Streamlit旧版.cmd` 回退；它不属于本次 React 工作台演示。
