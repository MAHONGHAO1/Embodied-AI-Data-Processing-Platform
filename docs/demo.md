# V0.4 · 8 分钟面试演示路线

这条路线展示固定机器人数据如何从可追溯的原始输入，经过人工决策与程序验证，成为可独立加载的交付包。先按 [SOP](SOP.md) 准备环境。八个业务节点始终可见：**上传／导入 → 数据清洗 → 数据筛选 → 数据标注 → 标注审核 → 数据质检 → 格式转换 → 打包交付**。

面试前准备一个已完成批次用于查看证据，一个明确标记的故障副本用于排查演示。完整重跑需要另留处理时间；讲解时不要修改正在展示的已交付批次，筛选或标注变化会使旧输出过期。具体实测范围见 [V0.4 验收](VALIDATION_v04.md)。

| 时间 | 页面与操作 | 说明重点 |
| --- | --- | --- |
| 0:00–0:45 | 批次总览：选择已完成批次，展示八节点及各自状态。 | 自动节点接续运行，人工节点等待提交；每个节点都有输入、版本、尝试、输出与日志。 |
| 0:45–1:30 | 上传／导入：查看来源与管理副本；批次总览 → 任务浏览，浏览首／中／末帧。 | 固定 Panda／Lift **仿真测试片段**，3 条／174 帧；原件只读，状态 9 维、动作 7 维。 |
| 1:30–2:30 | 数据清洗：看覆盖和问题证据；数据筛选：看保留源任务 0、2 与排除原因，下载处理记录和筛选清单。 | 清洗检查结构和可读取性，不自动修复数值；候选 2 条／116 帧。 |
| 2:30–3:30 | 数据标注、标注审核：分别查看内容、退回意见及重新提交记录，下载标注和审核记录。 | 任务级标注与人工审核独立；机器人执行失败、数据异常和程序故障是三种不同结论。 |
| 3:30–4:30 | 数据质检 → 报告与历史：查看最终报告，下载 HTML 和 JSON；进入关联运行看自动阶段。 | 审核后重新读取源数据并核对候选、映射、标注及审核；不通过时有报告且停止下游。 |
| 4:30–5:30 | 格式转换：查看源 0、2 → 输出 0、1 映射、官方验证和第二条视频首帧。 | 官方写入 LeRobot v3.0；116 帧 float32 全量数值比对、每任务首中末与 DataLoader 批读取。 |
| 5:30–6:30 | 打包交付：查看独立解包验证、当前版本与整包 SHA-256，下载 ZIP。 | 包内有训练文件、来源、映射、标注、清洗筛选审核和质检证据；包存在不等于通过验证。 |
| 6:30–7:30 | 故障副本的数据清洗或运行记录：选择问题，查看文件、字段、行、节点和日志。 | 说明“在哪里、为什么、下一步怎么处理”；坏任务隔离，剩余合格任务继续。 |
| 7:30–8:00 | 回批次总览，说明版本与边界。 | 本机单用户、两个固定配置；不把加载成功描述为训练效果。 |

## 可以直接练习的开场

“这个作品集处理的是机器人任务数据。我把读取、质检、任务筛选标注、格式转换和交付验证做成一条八节点流程。重点是每次处理都有输入版本、节点结果和日志；出错后能定位到具体任务、字段或行，未经验证的产物不会进入交付。这里演示的是公开 Panda／Lift 仿真测试片段，最终用官方 LeRobot 加载器检查输出。”

项目中哪些部分由自己设计、实现或借助工具完成，应按真实参与方式说明。对上游公开数据、官方库与自主开发的工作台模块分别署名，不把公开数据采集或机器人控制算法说成自己完成。

## 可以打开的故障证据

**HDF5 业务闭环：** 使用 SOP 中 `make_demo.py --scenario isolated` 制作的副本。任务 0 的 `actions[2]` 行 10 为 NaN；任务 1 缺少 `obs/robot0_eef_pos`；任务 2 不变。展示问题、隔离原因、只保留任务 2 后的审核与 57 帧转换交付。

**SO-100 按行定位：** 展开高级工具，在样本页面选择“异常演示副本”，在报告中跳转到任务 0 行 50 的动作 NaN。历史基线为 7 条问题，当前结果以本次报告为准。

**执行故障：** “视频缺失演示副本”展示读取失败与未检查项；“运行超时演示”展示任务 0 视频节点的人为等待、工作进程终止和其他任务继续。超时演示未破坏源视频。

## 面试追问时打开这些证据

| 追问 | 查看位置 |
| --- | --- |
| 数据来自哪里？ | 批次总览 → 来源与字段；完整来源与输入清单记录版本和指纹。 |
| 清洗后改了什么？ | 清洗处理记录；本版数据值未修改，筛选记录列出任务级决定。 |
| 为什么卡在这里？ | 当前节点的原因、上游尝试、执行状态、日志与文件证据。 |
| 审核后还能改吗？ | 可以保存新内容，但需重新提交审核；旧产物标历史。 |
| 如何证明格式能用？ | 官方验证 JSON、首中末抽样、DataLoader 批读取与全量数值比对。 |
| ZIP 下载后还可靠吗？ | 整包 SHA-256；用 `verify-delivery --archive <实际下载路径>` 新建独立验证运行。 |

最终交付包验证不重新读取源 HDF5，源数值一致性来自之前的转换证据；H.264 编码有损，时间按 20 Hz 派生。输出全部属于 train，不表示完成训练评估。本项目未实现通用 MCAP、真实采集控制、多相机硬件同步、多人权限或云端调度，GitHub 发布与个人主页上线另行进行。
