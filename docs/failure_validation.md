# v0.1 故障处理验证记录（规则 0.1.2）

验证日期：2026-09-10。环境：Windows、Python 3.12、CPU、本机 Streamlit 页面。规则版本：0.1.2。

本记录描述中文错误提示、可切换故障副本与报告导出的验证结果。原始样本的初次获取和视频定位记录见 [初版验证记录](validation.md)；测试数量分别按各阶段记录。

## 实测结果

| 输入 | 数据异常 | 读取失败 | 未检查说明 | 已执行检查 | 全部通过的任务 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 原始公开样本 | 0 | 0 | 0 | 55 / 55 | 5 / 5 |
| 异常演示副本 | 7 | 0 | 0 | 55 / 55 | 4 / 5 |
| 视频缺失演示副本 | 0 | 1 | 2 | 52 / 55 | 4 / 5 |

三个输入各有 5 条数据表、3,562 行。异常副本仅修改任务 0 的行 50、100、150；三处注入触发七条规则记录，时间变化也影响相邻间隔与视频时间对应。视频缺失副本只移除副本中的任务 0 视频。三项视频检查无法完成，其中解码失败记录为读取失败，其余两项依赖检查记录为未检查说明。

原始样本的 15 个来源文件在最终复查中仍全部匹配下载清单 SHA-256；两个演示均从独立副本读取。此处的异常结果描述预设故障副本，不代表原始公开样本存在相同问题。

## 页面实操

- 异常副本：通过侧栏切换，运行质检后显示 7 条异常、55 / 55 项；点击跳转定位，实际落在任务 0 行 50（第 51 / 503 条记录），图像、数值与曲线可浏览。
- 视频缺失副本：任务 0 显示“本帧图像无法读取：所需文件不存在……”中文说明，保留状态与动作展示。运行质检后正常生成 52 / 55 项报告；切换任务 1 后图像正常，任务检查通过。
- 无具体行位置的问题也能选择查看中文证据与原始诊断；不显示无效的行跳转按钮。
- 两种副本均实际点击并下载 HTML 和 JSON。读取浏览器落盘的两对文件，确认 HTML 内嵌 JSON 与下载 JSON 完全一致，页面统计对应的数据与两份报告一致。
- 浏览器下载报告的结果摘要与相同输入、参数下 CLI 报告的结果摘要一致。
- 窄窗口会收起侧栏，需要点击左上角双箭头展开；这不是检查流程停止。

## 自动检查

该阶段全套测试运行结果：64 项通过。随后调整无行位置问题的证据入口，相关 UI 测试再次运行：5 项通过。后者为相关测试的重跑结果，不与全套数量累加。

覆盖中文错误映射（文件、视频、Parquet、JSON、权限、下载）、副本来源标记、目标目录保护、原始文件保持不变、重复结果一致、视频失败后其他任务继续、首次生成副本、模式切换清理旧报告、定位与导出入口。原有缺字段、解码损坏等回归用例也继续通过。

## 复现入口

按 [标准 SOP](SOP.md) 完成依赖安装和样本获取后，在项目根目录运行：

```powershell
uv run robodata make-failure-demo
uv run robodata check --data-root work/failure_demo --output reports/failure-demo
uv run robodata make-failure-demo --scenario missing_video
uv run robodata check --data-root work/missing_video_demo --output reports/missing-video-demo
uv run pytest -q
```

视频缺失的检查命令返回码为 2，表示含读取失败；HTML / JSON 已正常写出。异常副本的数据可读，报告生成完成后命令返回 0；必须结合报告中的数据异常与覆盖信息判断数据质量。

上述命令分别在 `reports/failure-demo/` 和 `reports/missing-video-demo/` 生成 HTML / JSON 报告。这些目录保存本地生成结果，由 Git 忽略；克隆仓库后需执行命令生成。页面操作步骤见 [标准 SOP](SOP.md)。

## 边界

中文化覆盖应用主错误提示和可读报告。原始错误详情保留底层诊断；机器 JSON 键、来源字段名、关节名及框架连接状态仍可能为英文。此次验证未证明任何未知格式或故障都能继续；元数据无法读取等全局前置失败会显示中文说明并停止本次操作。

该阶段验证覆盖本地基础质检流程，未涉及自动数据修复、模型训练或公共在线服务部署。
