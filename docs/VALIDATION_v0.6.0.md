## 测试中发现的问题与失败门禁证据

1. `episode.tasks[0]` 实际存的是任务文本，最初按索引解析会失败。读取逻辑现兼容文本或索引，回归测试覆盖两种情况。
2. 来源 `next.done` 值为 Python `bool`，元数据 shape 为 `[1]`；未经规范化会被 LeRobot writer 拒绝。转换器现按 feature 的 dtype 和 shape 转为 NumPy 数组，标量布尔 shape 测试通过。
3. 五条审核后子集被错误地按 50 条原始集检查，导致官方加载后输出质检拒绝。现通过固定子集 profile 和源 episode 映射清单验证 5 条派生数据，同时仍要求原始固定 ALOHA 来源有完整 50 条。真实样例端到端重跑后输出质检通过。
4. 故障代码测试覆盖损坏／不匹配下载字节、缺少相机文件、视频帧数或时间映射异常、未知数据结构、格式写入失败和未验证结果拒绝登记。业务层另有源／证据修改、无效证据、打包失败和篡改验包的门禁测试。
5. 两次早期 ALOHA 运行分别在格式写入和输出质量门禁失败；它们都没有登记转换输出或 ZIP，诊断保留在 `artifacts/aloha-r2/`、`artifacts/aloha-r3/`。修复后第四轮完整通过。
