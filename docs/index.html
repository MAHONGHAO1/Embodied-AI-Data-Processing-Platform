01 / 做什么

把数据变成可交付产物

固定来源 → 逐路检查 → 官方格式转换 → 输出质检 → 打包与独立验包。每一步留下阶段状态、日志和文件证据。

02 / 数据从哪来

固定版本，不临时抓取

ALOHA Coffee 锁定 revision 与 10 个文件的 SHA-256（MIT 许可）；SO-100 用固定子集。基金部分为离线合成组合，界面明确标注。

03 / 凭什么信

能回到文件的证据链

55/55 项输出质检、官方 LeRobot 离线加载、ZIP 独立解包；失败运行不登记为交付物。不把界面通过当成数据通过。

06

能证明什么，不能证明什么

两仓文档与发布说明都按这个口径写。把边界写清楚，比把功能说满更有用。

能证明

  • 固定公开样例的逐路质检、官方格式读写与独立验包链路可复现
  • 交付包四路视频在相同帧索引下都能解码出画面，帧数与时间映射检查通过
  • 失败运行不会被登记为可交付产物，源文件哈希处理前后一致
  • 数据来源、回退原因与失效指标在界面和报告中一致呈现
  • 锁定依赖、持续集成与干净克隆安装均可复核

不能证明

  • 验收脚本使用明确标注的模拟审核门禁，不代表人工审核或机器人执行结果
  • 时间轴是静态帧序列，不代表硬件相机同步，也不等于工作台实时播放
  • 不代表模型训练效果、任务成功率或通用数据集适配
  • 基金持仓为虚构合成组合，不连接账户、不执行交易、不提供投资建议
  • 16:9 新工作台是布局重构，不改变数据验收范围；带「构造元数据」标记的四相机截图不作为业务状态证据
  • 两个服务仅监听本机地址，本页为静态展示，不提供在线交互服务
面试追问时打开哪里
追问证据入口
数据来自哪里？批次总览的固定版本、许可与来源信息；逐项校验见 v0.6.0 验收记录。
多相机如何检查？Episode 浏览器的逐路检查状态、本页四路同步时间轴，以及验收记录中的视频、帧数与时间映射结果。
时间轴上的帧是录屏吗？不是。来自交付包四路 H.264 视频按相同帧索引解码拼接；参数与逐路亮度核验见 timeline/manifest.json。
v0.9.0 修了什么？修复「提交审核后离开一小时，回来像全部回退到导入阶段」：读路径改为纯只读、SSE 终态主动结束、阶段进度按真实审核与产物推导、旧 Streamlit 入口同纪律，并补上 409「确认并重试」。根因与剩余风险见仓库 docs/LAUNCH_AUDIT_REPORT.md。
16:9 新界面改了什么？固定 Shell、局部滚动、四路相机与曲线共用一条时间轴、全宽 32px 表格与行检视联动；两仓 v0.8.0 / v0.3.0 发布说明列出完整改动与验证。
新界面截图都是真实业务状态吗？不是。带「构造元数据」标记的四相机布局验证图使用真实交付帧 + 构造的批次元数据；其余三张来自本机真实 FastAPI 服务，README 逐张注明来源。
工作台能在线打开吗？不能。两个服务只监听 127.0.0.1；本页是静态展示，不提供公网交互实例，也不改变「仅本机运行」口径。
转换用了官方格式吗？交付核验的官方 LeRobot 离线加载记录与数据字典；格式读写由官方库完成。
失败时会怎样？运行诊断、失败用例与验收记录中的登记门禁；失败运行不会成为可交付产物。
截图有没有修饰过？没有。均为本机实际运行截图或真实视频抽帧，仅做拼接与标注；历史界面已单独标注版本。
这证明机器人或模型有效吗？不证明。验收范围是数据读取、逐路检查、格式转换与交付。

本地运行

界面本身需要本机启动；本页提供的是无需安装即可核对的入口与证据。

# 具身数据平台（Windows / Python 3.12 / Node.js 24 / uv）
uv sync --locked
cd frontend && npm ci && npm run build && cd ..
.\启动工作台.cmd
# http://127.0.0.1:8765/

# 基金助手（默认离线合成演示）
.\启动基金助手.cmd
# http://127.0.0.1:8766/

完整步骤、首次安装脚本与复现验收命令见两仓 README。旧版 Streamlit 入口保留为回退；历史逐节点截图与 v0.4.0 验收报告见 归档页。本页的帧序列与图集由 docs/assets/timeline/manifest.json 记录来源与采样参数，可对照交付包视频复核；v0.8.0 / v0.3.0 的四张 16:9 界面截图及构造元数据标记见两仓发布说明。
