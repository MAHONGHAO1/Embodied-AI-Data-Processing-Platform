# 可复现规模实验 · 2026-11-12

## 范围

测量 `robodata.quality.run_checks(episode, check_video=False)` 对固定宽度 Episode 表格的**当前表格质检路径吞吐**。每行含 6 维 `observation.state` 和 6 维 `action`，并执行必需字段、行数、身份、形状、有限数值、帧索引与时间戳检查。

**不包括** fixture 构造、Parquet 读取、文件指纹、视频解码、LeRobot 转换、压缩打包、并发请求或服务开销。因此这不是端到端处理性能，也不能外推成生产容量或相对旧版本的提速。

## 可复现命令

在仓库根目录的 Windows 环境运行：

```powershell
.\.venv\Scripts\python.exe scripts\benchmark_quality.py --rows 1000,5000,10000 --repeats 3 --dataset-root work\aloha-integration-r4\runs\20261108T181145_5196ba6cceb7\unpacked\dataset --output docs\benchmarks\quality-table-2026-11-12.json
```

脚本固定使用零向量状态、单位向量动作与 30 FPS 等间隔时间戳；数据构造在计时区外。每个规模独立重复 3 次，报告中位数、最小／最大耗时和 records/s。运行环境及原始结果见 [JSON 结果](quality-table-2026-11-12.json)。

## 实测结果

环境：Windows 11、Python 3.12.10、Intel x86-64 处理器（系统报告 20 个逻辑 CPU）、pandas 3.0.5、NumPy 2.5.3。单进程、单次检查，视频检查关闭。

|---:|---:|---:|---:|---:|
| 1,000 | 0.012824 秒 | 0.012143–0.013252 秒 | 77,979 | 0 |
| 5,000 | 0.060775 秒 | 0.059667–0.062447 秒 | 82,271 | 0 |
| 10,000 | 0.121827 秒 | 0.117964–0.125474 秒 | 82,083 | 0 |

每行结果中的 `incomplete` 是预期状态：实验显式关闭视频检查，所以总体质检不应伪装成完整通过；表格检查没有数据问题。三档吞吐处于同一数量级，但样本只有每档 3 次、没有并发／磁盘／视频开销与更大规模数据，不能据此宣称线性扩展或可承载某个生产容量。

## 真实样例交叉检查

同一次脚本运行还加载了本地已验收的固定 ALOHA Coffee Episode 0：1,100 行、50 FPS、`lerobot/aloha_static_coffee` revision `b144896feb1f37398a862927b22cd3abdf005a6b`、格式 v3.0。Parquet 文件 SHA-256 为 `29c031583a0957a235b25656c8558e96ae3c5b74484408df3d46e21f2c858d29`。单次 `load_episode` 为 0.075517 秒（仅观察值，不作稳定 IO 基准）；同一已载入表格执行 3 次表格检查，中位数 0.012912 秒，约 85,193 行/秒，三次均 0 个表格数据问题。仍关闭视频检查，因此结果状态为不完整是预期的；这不是 ALOHA 全链路耗时。原始哈希与所有结果字段保存在 JSON 原始结果中。
