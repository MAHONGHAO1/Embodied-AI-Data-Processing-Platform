# 端到端小样本基线 · 2026-11-18（2 Episode，full 模式）

## 这条基线回答什么

固定来源的 2 条 SO-100 Episode，从下载清单一路跑到交付 ZIP 的独立验证，**每一步都实际执行**。它用来发现“哪个阶段真正花时间”，而不是证明生产容量。

- 样本：上游 revision `54141acb0bd6bcb868e34b4eb328f26481d333b2` 的 Episode 0–1，9 个文件，19,215,391 字节。
- 规模：2 Episode / 1,300 帧 / 单相机 640×480 / 30 Hz。
- 环境：Windows 11、Python 3.12.10、Intel64 Family 6 Model 154、CPU、单进程；主环境与 `tools/conversion` 隔离环境均为 `uv sync --locked`。
- 命令：

```powershell
uv run --locked python scripts\verify_pipeline.py `
  --sample work\samples\so100-e0-1 `
  --episodes 0-1 `
  --mode full `
  --output work\acceptance\pipeline-full.json
```

`full` 模式包含 `fast` 的全部阶段，另加原始预览和输出视频抽帧比对，因此阶段数从 8 个变为 9 个。

## 实测阶段耗时

| 阶段 | 实际内容 | 耗时 |
| --- | --- | ---: |
| `source_verify` | 9 个文件对 `source_manifest.json` 逐一哈希 | 0.05 s |
| `import_quality` | 导入、基础清洗检查、22 项覆盖 | 7.97 s |
| `raw_preview` | 原始视频 6 个位置抽帧，`480×640×3` | 2.03 s |
| `review_fixture` | 2 条验收审核夹具 | 0.20 s |
| `conversion` | v2.0 → v3.0、官方离线加载、输出质检 | 48.14 s |
| `output_frames` | 6 个输出位置与转换运行保存的解码像素逐一比对 | 1.55 s |
| `dataloader_probe` | 官方 `LeRobotDataset` + `DataLoader` 前 4 个 batch | 31.23 s |
| `delivery` | 打包、独立解包、官方加载 | 14.88 s |
| `zip_verify` | ZIP 路径安全与独立交付验证 | 0.05 s |
| **合计** | 9 个阶段 | **约 106.1 s** |

导入批次即便重复运行也会新建运行目录，因此上表是“从零到交付”的单次观察，不是缓存命中后的重复运行时间。同一版本前一次完整运行合计约 126.0 秒（转换 58.50 s、DataLoader 37.43 s、交付 18.59 s），说明单次基线存在约 15–20% 的运行间波动。

## DataLoader 探针

| 字段 | 值 |
| --- | --- |
| 加载器 | `lerobot 0.4.4` · `torch 2.7.1+cpu` |
| 配置 | `batch_size=8`、`num_workers=0`、`shuffle=False` |
| 加载样本 | 4 个 batch / 32 帧 |
| 数据集加载 | 0.089 s |
| 解码耗时 | 23.373 s |
| 吞吐 | 1.37 帧/秒 |
| 加载帧数 | 1,300（与清单一致） |
| 动作／状态 | `float32 [B,6]`，全部有限 |
| 图像 | `float32 [B,3,480,640]`，值域 `[0,1]` |
| 顺序 | 首尾动作与 `dataset[0]` / `dataset[-1]` 逐元素相等 |

`num_workers=0` 是刻意的：探针要给出确定性的顺序与错误信息，不测并行加载吞吐。同一台机器前一次 `full` 运行是 29.497 s / 1.08 帧/秒，更早的 `fast` 运行是 15.3 s / 2.09 帧/秒；三次相差约 2 倍，说明这个探针受系统负载与视频定位缓存影响很大，**不能**把单次数字当成稳定吞吐，更不能外推成训练吞吐或 GPU 性能。

## 怎么读

- 转换占接近一半时间（48.1 s），其中包含官方 writer 写视频、元数据升级和官方离线加载；这是当前链路的真实主成本。
- 导入 + 质检约 8.0 s，说明表格路径不是瓶颈。
- DataLoader 探针 31.2 s 只解码 32 帧，提示训练侧若随机访问视频帧，解码策略比表格检查更值得优化。这里没有做优化，也没有声称优化。
- 打包与独立验证约 14.9 s，成本主要来自重新解包和官方加载，而不是 ZIP 压缩本身。

## 边界

- 2 Episode 子集不代表 SO-100 全量 50 条 / 32,068 帧，也不代表 ALOHA 四路相机。
- 单次运行、单机、CPU；没有重复测量、方差、内存峰值、并发或磁盘 IO 分离。
- 审核标签是脚本写入的流程夹具，不代表源任务成功或失败。
- 不证明策略训练、任务成功率、硬件同步、Docker 内转换或生产容量。
- ZIP 整包 SHA-256 随运行时间戳变化，不是跨运行常量；可复现的是输入哈希、Episode 数、帧数和各阶段结论。
