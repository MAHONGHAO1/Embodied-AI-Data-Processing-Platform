## 邀请方式

把仓库链接和 [REPRODUCTION.md](REPRODUCTION.md) 一起发给对方，请对方只回答可核对的事实：

1. 操作系统、Python / uv 版本；
2. 执行了哪条命令（Tier 1 / Tier 2 / 完整）；
3. 卡在哪一步，报错原文是什么；
4. 是否有网络限制（`huggingface.co`、镜像、代理）；
5. 总耗时与是否成功产出 `pipeline-*.json`。

不需要对方提供真实姓名或账号；如果对方同意公开，只记录其愿意公开的称呼与链接。也可以在仓库里直接使用 [独立复现报告](https://github.com/MAHONGHAO1/Embodied-AI-Data-Processing-Platform/issues/new?template=reproduction.yml) issue 模板。

## 处理规则

- 只有实际收到的反馈才能进表；转发、猜测或自己模拟的「用户反馈」不算。
- 失败记录同样保留。修复后在「是否已修复」写对应提交或版本，不改写原始报错。
- 若对方要求删除记录，删除整行，不保留匿名化摘要。
- 外部反馈不改变「不证明策略训练效果、硬件同步或生产容量」的边界。
