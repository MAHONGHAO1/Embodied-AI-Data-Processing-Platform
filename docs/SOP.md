# RoboData 工作台 V0.4 · 标准操作 SOP

适用：Windows、本机单用户、Python 3.12、CPU。更新：2026-09-11。本文对应 V0.4 业务页面；实际应用版本看页面侧栏，LeRobot **数据格式版本 v3.0** 与应用版本分别记录。文中的任务数和帧数是固定样本的操作预期，实际是否通过，请以本次报告与验收记录为准。

版本口径与实际验证范围见 [V0.4 状态](STATUS_v04.md)和 [V0.4 验收](VALIDATION_v04.md)。首次使用可先按第 3–7 节跑一个批次；面试演示可按 [8 分钟路线](demo.md)查看现有证据。

> 完整体验：上传／导入 → 数据清洗 → 数据筛选 → 数据标注 → 标注审核 → 数据质检 → 格式转换 → 打包交付。导入后自动做基础清洗检查，再等待人工筛选、标注和审核；固定 HDF5 的候选审核全部通过后，自动执行最后三步。

## 1. 启动、准备与停止

获取源码后，在文件资源管理器中打开包含 `app.py`、`pyproject.toml` 和 `启动工作台.cmd` 的项目根目录。获取源码与环境要求见 [项目 README](../README.md)。

双击 **启动工作台.cmd**，保留启动窗口，可以最小化。浏览器打开 [本机工作台](http://127.0.0.1:8501/)。地址只供本机访问；已有服务正常运行时不必重复启动。侧栏收起时点击左上角展开。

首次安装或样本缺失时，在项目根目录 PowerShell 依次执行：

```powershell
uv sync --frozen
uv sync --project tools/conversion --frozen
uv run robodata fetch-hdf5
# 使用 SO-100 旧功能或目录导入时再获取：
uv run robodata fetch-sample
```

HDF5 默认下载到 `data/robomimic/test.hdf5`，约 46 MB；SO-100 下载到 `data/so100_sweet_pick/`，约 53 MB。独立转换环境另含 CPU PyTorch 等依赖，HDF5 导入预览也需要此环境。代理仅对当前下载进程配置，不写入公共代码或修改系统网络。

本机同时只处理一个长运行。开始导入、质检、转换或打包前，先看是否已有活动运行；普通标注保存仍可进行，但内容变化会使旧快照失效。

关闭或刷新网页不会停止后台处理，也不会重新执行任务。停止使用时，先等处理运行结束，再在启动窗口按 `Ctrl+C` 停止页面服务。重新启动后，磁盘上的批次和历史仍可读取。

## 2. 导航与八个业务节点

默认进入 **批次总览**，在同一批次上依次处理八个节点。即使上游未完成，下游仍可查看等待原因。

| 节点 | 主要操作 |
| --- | --- |
| 上传／导入 | 固定配置的本地路径／文件上传、管理副本与原始预览。 |
| 数据清洗 | 基础结构与可读取性检查、自动保留／隔离建议、清洗处理记录。 |
| 数据筛选 | 人工保留／隔离／排除、确认候选集、筛选清单。 |
| 数据标注 | 任务描述、执行结果、标签与备注、保存或提交标注。 |
| 标注审核 | 核对提交内容、退回修改或审核通过。 |
| 数据质检 | 审核后的最终数据、映射与标注检查。 |
| 格式转换 | 已审核且最终质检通过的候选集转换与官方验证。 |
| 打包交付 | ZIP 生成、独立解包验证、下载与重新验证。 |

每个节点下方的 **节点输入、进度与输出** 显示状态、结论、原因、版本、本次及上游尝试；展开 **当前输入、已保存中间产物、节点输出** 可查看实际文件、哈希与有效性，使用 **下载所选实际文件** 获取当前可用文件。上方的八节点进度条和侧栏进入同一组独立节点，后续节点会沿用本批次输入，无需逐步重新选文件。

侧栏保留 **批次总览、八个业务节点、运行记录**。辅助功能按当前批次收纳：

| 要做的事 | 现在的入口 |
| --- | --- |
| 查看批次统计、任务清单和流程状态 | 批次总览 → 数据概览 |
| 浏览当前批次图像、状态／动作和问题位置 | 批次总览 → 任务浏览，也可点击“浏览本批次任务” |
| 核对来源版本、字段维度和分量顺序 | 批次总览 → 来源与字段 |
| 执行最终质检 | 数据质检 → 当前质检 |
| 看当前报告、选择历史运行的报告并下载 | 数据质检 → 报告与历史 |
| 排查运行节点、错误与日志 | 运行记录；也可在历史报告点击“查看该报告的节点与日志” |
| 独立样本浏览、故障演示、固定公开样本转换 | 展开侧栏“高级工具” |

“报告与历史”只列当前批次的历史报告，显示原运行时间与内容版本；历史证据不替代当前交付结论。报告文件损坏时仍可进入对应日志。顶部八节点进度条可点击跳转；刷新后保留页面与批次。

“高级工具”包含 **样本数据概览、样本任务浏览、样本质检报告、公开样本转换**。其中“公开样本转换”保留固定 demo_0–2 的直接转换验证，不经过业务审核流程。进入样本工具会移除所选业务运行的报告上下文，避免把业务批次结果套到独立样本上；返回业务页面仍保留选中的批次。

批次顶部保留业务阶段、导入数、候选数、待审核数、内容版本和保存修订号。业务审计记录人工决定，程序运行与日志记录处理过程。

## 3. 导入 HDF5 并做转换前预览

1. 进入 **上传／导入 → 导入一个本地批次**。
2. **导入方式**选 **本机 HDF5 路径**，填写名称，例如“Lift 非连续任务演示”，以及完整 **本机输入路径**。也可选 **上传 HDF5 文件**，通过 **选择 HDF5 文件**选取本机文件。
3. 原始公开样本不要填写测试副本说明。仅导入明确制作的故障副本时，展开 **故障副本标记（仅测试输入填写）**，填写真实用途。
4. 点击 **开始导入**。在运行记录观察复制与校验输入、原始预览解析、批次登记、基础清洗检查与结果回写。
5. 完成后点击 **返回关联批次**。也可回批次总览选择批次，再点 **刷新批次状态**。
6. 进入 **批次总览 → 任务浏览**，查看当前批次清单和预览。
7. 在 **选择源任务**中依次选任务 0、1、2。展开 **图像与状态／动作预览**，点 **首帧／中间帧／末帧**，或拖动 **任务内记录位置**。

HDF5 下载完成后，在项目根目录执行以下只读命令，取得可粘贴到输入框的完整本机路径：

```powershell
(Resolve-Path -LiteralPath '.\data\robomimic\test.hdf5').Path
```

上传文件也只保存在本机。导入创建管理副本，原件保持不变。同一输入指纹不会重复建立批次，重复导入会返回已有批次。批次登记后，导入运行继续执行基础清洗检查。应分别查看各节点，批次已出现不代表后续检查完成；基础清洗完成也不代表人工审核、最终质检或交付完成。

上传入口仍受固定 HDF5 配置与来源校验约束，不支持任意文件自动推断。测试副本需显式标记，仍会进行结构与质量检查；严重损坏的文件可能在导入预览节点失败。

| 固定配置 | 操作时核对 |
| --- | --- |
| 来源 | robomimic 公开仓库，固定版本 `74fa018461f479cd9fd15b924a16103012096203`，来源卡声明 MIT。 |
| 数据性质 | Panda／Lift 仿真测试片段，不能称为真机采集。 |
| 导入选择 | demo_0、demo_1、demo_2，预期 59、58、57 帧，合计 174 帧。 |
| 状态／动作 | 9 维状态、7 维动作，各自保留来源分量顺序。 |
| 图像与时间 | agentview，84×84 RGB；任务时间按 `frame_index / 20` 派生。 |
| 来源统计警告 | 文件全局标注 9666，实际 10 条 demo 共 531 帧；当前批次按所选任务重新统计。 |

来源统计说明不等于阻断性数据问题，不能直接解释为当前 174 条记录缺失；也不能据此放行 NaN、缺字段或长度不一致。预览和检查证据一起用于判断。

## 4. 基础清洗、定位问题与确认筛选

1. 导入运行结束后，进入 **数据清洗**，核对基础检查结论与规则覆盖。固定 HDF5 是 10 类规则 × 3 条任务，预期 30 项；不要与 LeRobot 输出或最终质检的项数混用。
2. 若需要重新检查，点击 **重新执行基础清洗检查**，到运行记录观察结果。重跑会更新筛选建议并要求重新确认、提交审核。
3. 有问题时选择源任务，在 **选择问题证据** 中核对规则、字段、文件、行和证据。有行位置时点击 **定位到问题记录**；行索引从 0 开始。可 **导出清洗处理记录 JSON**。
4. 进入独立的 **数据筛选** 节点。完整通过的任务可保留；异常、读取失败或检查不完整的任务隔离。隔离与排除必须填写原因。
5. 演示非连续选择时，可将源任务 1 的 **筛选决定** 设为排除，填写“本次选择任务 0 和 2，用于验证非连续任务映射”，点击 **保存筛选决定**。这表示选择范围，不表示任务 1 有质量问题。
6. 核对候选任务 0、2 共 116 帧，排除任务 1 共 58 帧，合计应与导入清单一致。点击 **确认筛选候选集**，可 **导出筛选清单 JSON**。

基础清洗采用检查与建议，不删原件、不插值、不修复轨迹。最终数据质检在标注审核后另行执行。没有保留任务时不能确认；筛选变化后需重新确认，所有保留任务需重新提交审核，已填写标注文字会保留。导出的清洗记录与筛选清单是决策和数据引用，不是重新生成的完整训练数据集。

## 5. 数据标注、退回修改与审核

1. 进入 **数据标注**，选择保留任务，结合预览填写 **任务描述、机器人任务执行结果、标签（逗号分隔）、标注备注**。
2. 判断依据不足时选“不确定”。未完成可 **保存草稿**；准备好后 **保存并提交审核**。任务描述非空、结果已标注且候选集已确认，才能提交。可 **导出标注文件 JSON**。
3. 进入独立的 **标注审核** 节点，查看已提交的内容与原始预览。
4. 需修改时填写 **审核意见／退回原因（退回必填）**，点击 **退回修改**；返回数据标注修改，再保存并提交，然后回审核页复核。
5. 点击 **审核通过**。所有保留任务均需审核；可 **导出审核记录 JSON**。
6. HDF5 最后一条保留任务审核通过后，自动启动“最终质检 → 转换 → 打包验证”，进入运行记录。若因已有活动运行等原因提示审核已保存但自动处理未启动，等待活动运行结束，再到数据质检节点点击 **执行最终质检并自动继续**。

机器人执行失败、数据质量问题、处理程序失败分别记录。完整的失败尝试也可作为有效数据保留。该功能是本机单用户的任务级标注审核，不包含多账号分权或逐帧框选。

修改已审核标注会回到草稿并使旧输出失效。页面修订过期时刷新后核对，避免用旧内容覆盖新决定。

## 6. 最终数据质检与格式转换

1. 进入 **数据质检**，查看当前候选的最终检查状态。该检查在人工审核后执行，核对候选数据、映射、标注完整性和审核状态，保留此前的人工审核决定。
2. 若自动流程已经运行，查看节点与运行记录即可；若未启动或处理问题后需要重试，点击 **执行最终质检并自动继续**。
3. HDF5 最终质检通过后自动进行候选转换及打包验证；规则未通过或进程失败会保留报告并停止后续步骤。SO-100 可执行最终质检，当前没有其转换交付适配器。
4. 进入 **格式转换**，核对源／输出任务映射、候选快照和转换证据。当前内容版本未通过最终质检时，手动 **转换并验证候选集** 按钮会被阻止。
5. 官方验证按实际候选帧数核对 float32 数值、每任务首／中／末样本与 DataLoader 批读取。保留源任务 0、2 时，输出编号 0、1，共 116 帧；全部保留则为 174 帧。
6. 展开当前输出的 **预览当前 LeRobot 输出与视频偏移**，检查第二条输出任务的首帧及共享 MP4 的偏移。通过当前节点输出文件区查看清单、标注与报告。

三个检查阶段的对象不同：基础清洗检查导入任务是否完整可读；最终质检重新读取源数据，并检查保留候选的映射、标注和审核；输出质检检查实际写出的 LeRobot 文件。保留源任务 0、2 的示例分别对应 30 项基础检查、18 项最终检查、22 项输出检查，数量不能互相替代，结果以当前运行报告为准。

在数据质检节点使用 **下载本节点质检报告 HTML／JSON** 导出最终报告。在运行记录中分别查看 **官方加载与批读取验证**、**交付包官方离线加载验证**：前者包含源 float32 数值比对，后者只检查解包输出并官方加载，不重复读取源 HDF5。两份证据分别提供 JSON 下载。

相机编码为有损 H.264；时间按 20 Hz 派生，不代表硬件同步。输出归入 train 不代表完成训练评估。源描述与人工标注映射随输出保留。

自动流程、手动重试都按当前内容版本处理。运行期间修改筛选或标注，旧快照的产物不能作为新内容的有效输出；应按最新候选重新验证。

## 7. 打包、下载并独立验证下载包

1. 进入 **打包交付**，查看自动流程生成的当前交付记录；需要手动打包时先 **选择当前已验证输出**。
2. 自动流程已完成打包时可直接核对结果；需要新建包时点击 **生成并验证交付包**。手动打包使用当前已验证输出。
3. 观察生成 ZIP、独立解包与清单校验、交付包官方离线加载、结果回写。文件写出不等于可交付，必须以验证和登记结果为准。
4. 在打包交付页核对内容版本、任务数、帧数、数据格式、包大小、SHA-256 和运行编号。
5. 点击 **下载已验证交付包 ZIP**。从浏览器下载记录确认保存位置，通常是 Windows“下载”目录。
6. **重新独立验证此包**验证管理目录中的 ZIP；核验刚下载的文件时，执行以下命令并替换为实际下载路径。

```powershell
# 整包哈希应与打包交付页显示的 SHA-256 一致。
Get-FileHash -Algorithm SHA256 -LiteralPath 'C:\实际下载目录\delivery.zip'

# 在项目根目录运行：新建运行、独立解包并再次官方离线加载。
uv run robodata verify-delivery --archive 'C:\实际下载目录\delivery.zip'
```

交付包主要包含：

```text
dataset/                              LeRobot v3.0 数据、视频与元数据
documents/annotations.json            人工标注
documents/mapping.json                源／输出编号、版本与快照
documents/source.json                 来源信息
documents/cleaning_summary.json        筛选决定与原因
documents/cleaning_record.json         基础清洗策略与无数值修改记录
documents/selection.json               候选集与排除／隔离原因
documents/review.json                  当前保留任务的审核记录
documents/final_quality.json           审核后最终质检证据
documents/quality_report.json          输出质检证据
documents/conversion_verification.json 官方转换验证证据
documents/SOURCE_LICENSE.txt           来源许可声明
manifest.json                         相对文件清单与逐文件 SHA-256
README.md                             包内使用说明
```

清单不递归计算自身哈希，ZIP 整包哈希在包外记录。数据或 ZIP 在登记后变化时，不再提供有效下载。业务内容变化后，旧包保留为历史，不作为当前版本下载。

独立验证交付包不重新读取源 HDF5；源数值一致性来自此前转换验证随包保存的证据。包验证检查清单、表格及官方离线读取，不能描述为再次完成源数值比对。生成与下载 ZIP 都是本地操作，不会自动发布到 GitHub。

## 8. 出错时看哪里、如何恢复

先点选流程中的对应节点，在 **节点输入、进度与输出** 查看原因、上游尝试和文件证据。展开 **当前节点日志与尝试记录**，按 **任务筛选、尝试筛选、级别筛选** 查找事件，可 **下载当前筛选日志 JSONL**；人工节点的决定另存于业务审计。

从批次 **相关程序运行与日志 → 查看节点与日志**，或进入 **运行记录 → 选择历史运行**。按以下顺序排查：

1. **节点执行情况**：停在哪一步、执行状态、耗时与数据异常数。
2. **节点诊断与文件证据 → 选择节点**：中文原因、输入文件、字段与位置。
3. **运行日志**：按 **日志任务／日志节点／日志级别**筛选，展开完整事件与诊断。
4. **运行参数、产物和完整诊断**：输入快照、产物路径、原异常和堆栈；可选 **进程原始日志**并下载。
5. 显示产物待回写时，点 **核对并恢复业务登记**。恢复重新核对产物和版本，不强行登记过期结果，也不重复登记同一结果。

| 状态 | 含义与下一步 |
| --- | --- |
| 数据异常 | 已读取并发现问题；去清洗筛选看证据、定位和隔离。 |
| 执行失败／读取失败 | 文件、结构、环境或写入步骤未完成；保留诊断，处理原因后创建新运行。 |
| 执行超时 | 节点超过预算并终止工作进程；查看预算和最后日志。 |
| 未检查／未执行 | 前置条件失败，不能算合格；先处理上游原因。 |
| 待回写 | 产物与业务登记尚未闭合；核对恢复，不能只凭目录存在判成功。 |
| 历史／已过期 | 内容版本变化；保留历史证据，当前处理需要新快照。 |
| 页面内容已过期 | 存在新保存；刷新后核对，不自动覆盖。 |

默认本机目录：


## 10. 常用命令、常见问题与范围

以下命令在项目根目录 PowerShell 执行；尖括号表示需要替换的实际编号。`revision` 使用 **show-batch**返回的保存修订号，不是内容版本。

```powershell
uv run robodata batches
uv run robodata show-batch <batch_id>
uv run robodata show-flow <batch_id>
uv run robodata import-batch --input '.\data\robomimic\test.hdf5' --source hdf5 --label 'Lift 本地批次'
uv run robodata check-batch <batch_id> --revision <revision>
uv run robodata final-check-batch <batch_id> --revision <revision>
uv run robodata final-check-batch <batch_id> --revision <revision> --check-only
uv run robodata convert-batch <batch_id> --revision <revision>
uv run robodata deliver-batch <batch_id> --output-id <output_id> --revision <revision>
uv run robodata reconcile-run <run_id>
uv run robodata runs
uv run robodata show-run <run_id> --events
```

筛选与人工审核按页面完成。CLI 和页面共用业务接口与运行锁。长操作默认等待，可加 `--no-wait`只返回运行编号。`final-check-batch` 默认通过最终质检后自动转换和打包，`--check-only` 只执行最终质检；`convert-batch` 先做最终质检再转换，完成转换即停止，不自动打包。最终质检规则不通过时 CLI 退出码为 2，程序执行失败为 1，通过为 0。

| 现象 | 处理 |
| --- | --- |
| CONNECTING／无法打开 | 检查启动窗口和服务，已有网页标签不代表服务仍在。 |
| 已有活动运行 | 到运行记录查看，不要反复点击启动。 |
| 转换按钮不可用 | 先读中文原因，再核对候选集、审核与数据配置。 |
| 看到英文日志 | 主错误说明为中文；原异常类型、库消息和堆栈保留用于诊断。 |
| 零异常但有未检查 | 不能算全部通过，先处理上游失败。 |
| 下载文件找不到 | 查看浏览器下载记录与保存目录。 |
| 8501 端口占用 | 已有本项目服务可使用；需要另一端口时用下方命令。 |

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\start.ps1 -Port 8502
```

随后打开 `http://127.0.0.1:8502/`；多个页面仍共享本机长运行限制。
